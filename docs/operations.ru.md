# Эксплуатация

[English](operations.en.md) · [Руководство](../README.ru.md)

## Развёртывание

Сервер — `185.251.89.19`, рабочий каталог — `/opt/apps/family_connect`.
Команды выполняются из него. Существующие сервисы MicroTrader относятся к другому проекту;
эти команды не должны их перезапускать или удалять.

```sh
docker compose build
sudo ./scripts/provision.sh
docker compose up -d control gateway relay-a relay-b
docker compose ps
curl -fsS http://127.0.0.1:18080/healthz
```

Подготовка использует `state-v2/`, сохраняя старые ключи в `state/`. Ключи создаются один раз;
повторный запуск использует их снова и не возвращает отозванным устройствам членство молча.
Лабораторный issuer CSR подготавливает gateway-lab, relay-a, relay-b, client и не включённое
в список тестовое устройство outsider. Администратор хоста имитирует раздельное хранение;
генерация ключей на реальных устройствах и публичная регистрация пока не встроены в мобильные приложения.

IP gateway и relay входят в подписанную конфигурацию стенда `172.29.92.0/24`.
Control plane доступен внутри неё по `172.29.92.2:8080`, а также имеет management-сеть для
порта на localhost хоста. Порты data plane в интернет не публикуются.

Удалённый просмотр API:

```sh
ssh -L 18080:127.0.0.1:18080 root@185.251.89.19
curl http://127.0.0.1:18080/v1/network-state
```

Не публикуйте стенд в интернете: публичная регистрация и production abuse management отсутствуют.

## Файлы и доверие

| Каталог | Содержимое / кому разрешено чтение |
|---|---|
| `state-v2/authority` | Приватный ключ CA; только администратор подготовки |
| `state-v2/control` | Ключ Ed25519 и каталог членства; control service/оператор |
| `state-v2/trust` | Публичный CA и закреплённый корень Ed25519; все узлы |
| `state-v2/<role>` | Собственный приватный ключ роли, публичный CSR, сертификат, identity |
| `state-v2/cache-<role>` | Подписанный кэш и защита от отката; соответствующая роль |

Runtime UID core — 65532. Каждый сервис получает только свой каталог identity, публичные
корни доверия и собственный записываемый кэш. Control service не получает приватные ключи
устройств и gateway. Не включайте каталоги `state*` в Git, контекст Docker-сборки и обращения
в поддержку. Для выпуска можно передавать публичные CSR/сертификаты; приватные ключи — нельзя.

## Изменение членства

Администратор запускает локальный инструмент с ограниченными mounts. Пример на сервере:

```sh
docker run --rm --network none \
  -v "$PWD/state-v2/control:/state:rw" \
  -v "$PWD/state-v2/client/cert.der:/device.der:ro" \
  -v "$PWD/state-v2/trust/ca.der:/ca.der:ro" \
  family-connect-control:auth2 python scripts/admin.py revoke \
  --certificate /device.der --ca /ca.der
```

Для возврата этого лабораторного устройства используйте `enroll` вместо `revoke`.
Каждое изменение создаёт новый epoch; не возвращайте старый network.json для отмены отзыва.
Не редактируйте членство вручную без увеличения epoch. Удалённого административного HTTP endpoint нет.

## Поведение при отказах

- Backend недоступен: проверенный кэш действует до подписанного срока, обычно 15 минут.
- Срок истёк: новые подключения запрещены, активные сессии закрываются.
- Другой корень, подмена или откат обновления: обновление отклоняется, действительный кэш сохраняется.
- Повреждённый кэш на диске: запуск закрывается с ошибкой. Нужно разобраться в причине,
  а не автоматически удалять защиту от отката ради запуска.
- Сертификат истёк: mTLS не устанавливается; автоматической ротации на этом этапе нет.
- Gateway отказал: тестовая передача завершается ошибкой; перенос интернет-потоков не реализован.

Bootstrap URL задаются через `BOOTSTRAP_URLS`, разделитель — запятая. Каждый источник должен
возвращать подписанный envelope того же формата. Публичный ключ подписи устанавливается только
доверенной подготовкой. Несколько URL одного сервера не создают независимые точки отказа.

## Обычная проверка

```sh
docker compose logs --tail 50 control gateway relay-a relay-b
./scripts/test_auth.sh
```

Логи содержат служебные события, а не payload или историю посещений. Артефакты тестов содержат
контрольные суммы синтетических данных и время; это не обезличенная production-телеметрия.
[Полные испытания отказов](testing.ru.md) намеренно останавливают сервисы/отзывают тестового
клиента, затем восстанавливают их. Выполняйте их только на данном стенде.
