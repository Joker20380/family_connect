# Windows 0.2: автономный клиент

## Статус

Новый клиент заменяет Windows-оболочку Python/Tk. Один установщик включает приложение, .NET runtime, службу Family Connect, встраиваемую библиотеку WireGuard и официальный подписанный драйвер WireGuardNT. Дополнительные установки пользователю не нужны. Поддерживается Windows x64; ARM64 отдельной сборкой пока не проверен.

Это пилот прямого подключения к российскому gateway. Адаптивная маршрутизация, семейная подписка и онлайн-приглашения ещё не подключены. Доверенной подписи издателя Family Connect пока нет: сборка `pilot-unsigned` не является коммерческим подписанным выпуском. Не отключайте антивирус и не добавляйте исключения для установки пилота. Если Windows блокирует файл, сохраните название обнаружения, путь и SHA256 для разбора.

## Первое подключение

1. Установите Family Connect. Права администратора нужны установщику; обычный интерфейс работает без повышения прав.
2. Нажмите «1. Получить код устройства». Приложение создаёт уникальный ключ на этом компьютере. Передайте код оператору: он содержит только открытый ключ.
3. Оператор регистрирует устройство на gateway и выдаёт файл `device.fcactivation`.
4. Нажмите «2. Открыть файл активации» и выберите этот файл. Активация привязана к вашему ключу и действительна для импорта 24 часа.
5. Нажмите «Подключить». Проверяйте доступность нужных сайтов: работа службы сама по себе не доказывает доступность интернета.

Вручную вводить IP, DNS и ключи не нужно. Linux использовал ранее настроенный профиль; Windows получает собственный ключ и адрес. Копирование Linux-профиля не требуется. Файл активации не содержит закрытого ключа и не активирует другое устройство. Уже принятая активация работает без control plane; срок импорта не является сроком подписки. Отзыв выполняется удалением peer на gateway, коммерческий механизм отзыва ещё не реализован.

## Изоляция и хранение

Служба LocalSystem создаёт отдельный ключ для каждой учётной записи Windows и хранит его в DPAPI текущего пользователя службы (SYSTEM), в `%ProgramData%\FamilyConnect`, с ACL только SYSTEM/Administrators. Закрытый ключ не передаётся в интерфейс, оператору или серверу. Named pipe разрешает локальные аутентифицированные подключения, запрещает сетевые и связывает запрос с SID вызывающего пользователя. Привилегированный API принимает только status/request/activate/connect/disconnect; команды, пути и произвольные конфиги не принимает.

Одновременно работает один туннель. Другая учётная запись не может переключить чужой активный туннель. Системный администратор остаётся доверенной стороной. Конфиги туннеля также DPAPI-зашифрованы; открытый конфиг не сохраняется на диск. Просмотры сайтов и содержимое трафика не логируются приложением. Диагностика WireGuard может содержать технические сведения о туннеле в системных журналах; это не обещание полного отсутствия технических журналов.

Закрытие интерфейса сохраняет VPN; остановка службы и удаление приложения отключают его. Автоподключение туннеля после перезагрузки не включено. При удалении программы защищённые данные устройства сохраняются для переустановки; полное удаление `%ProgramData%\FamilyConnect` администратором уничтожает локальные ключи и требует новой активации. Эта версия не даёт гарантии kill switch при остановке службы.

## Оператор: активация пилота

Закрытый ключ подписи активаций хранится вне Git в `state-client-build/activation/signing.key`; в приложение включён только `clients/windows/activation.pub`. Это не сертификат Authenticode: подпись активаций и подпись Windows-приложения решают разные задачи.

На доверенном компьютере оператора:

```sh
python3 scripts/activate_windows.py \
  --key state-client-build/activation/signing.key \
  --request FC1_PUBLIC_DEVICE_CODE \
  --number 4 --gateway-public BASE64_GATEWAY_PUBLIC_KEY \
  --output state-enroll/windows-device-4
```

Выберите свободный адрес 4–254. Перед передачей файла активации зарегистрируйте `peer.json` на управляемом gateway:

```sh
python3 scripts/register_pilot_peer.py \
  --peer /secure/path/peer.json \
  --keys /actual/project/state-v2/wireguard \
  --container ACTUAL_GATEWAY_CONTAINER
```

Регистратор проверяет конфликты адреса/ключа, сохраняет публичный peer и добавляет его без перезапуска существующего туннеля. Он требует новую версию `pilot/gateway.sh`, загружающую `peers/*.conf` при старте. Обновление старого образа gateway надо провести отдельно в согласованное окно: пересоздание контейнера прерывает соединения. Сам клиент и сборка ничего на серверах не развёртывают. Сервер `186.246.51.201` исключён из VPN-инфраструктуры.

## Сборка и доверенная подпись

На Windows-машине сборки нужны .NET SDK 10, Git, Inno Setup 6; зависимости VPN загружаются из официальных источников с закреплённой версией и SHA256. Это требования к разработчику, не пользователю.

```powershell
./clients/windows/build.ps1
# Только после получения сертификата издателя в Windows certificate store:
./clients/windows/build.ps1 -SignedRelease -SigningThumbprint CERTIFICATE_THUMBPRINT
```

Ключ сертификата должен быть доступен SignTool через сертифицированное аппаратное/облачное хранилище. Не передавайте закрытый ключ и пароль в чат или Git. Скрипт подписывает собственный EXE/DLL, tunnel.dll, установщик и деинсталлятор; проверяет доверие Authenticode и ожидаемый сертификат. Официальный драйвер сохраняет подпись WireGuard. Выпуск с `-SignedRelease` без сертификата завершается ошибкой, самоподписанный сертификат не подставляется.

Получение сертификата требует регистрации и проверки издателя у поставщика подписи. Даже доверенная подпись не гарантирует отсутствие SmartScreen/антивирусных предупреждений: нужен тест на чистой Windows, проверка Defender, разбор конкретных обнаружений и накопление репутации. Не меняйте сборку для обхода детектирования и не отключайте защиту.
