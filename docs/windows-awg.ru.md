# Windows AWG: активация и эксплуатация

Статус на2026-09-12: принятый в изолированном Windows CI preview, не опубликован и не установлен на пользовательские устройства.
[Приёмка и ограничения](releases/2026-09-11-windows-awg-integration.ru.md).

## Подготовка активации

Windows создаёт закрытый ключ локально; кнопка получения кода выдаёт FC1-код
публичного ключа. Оператор регистрирует этот публичный ключ на AWG gateway
185.251.89.19 с уникальным номером N (4..254), адресами 10.78.0.N и fd78:92::N
(последняя часть IPv6 — номер в шестнадцатеричном виде). Регистрация peer —
отдельная операция, issuer её не выполняет. Существующие peer не перезаписывать.

В локальном public-profile.json нужны ровно следующие поля:

```json
{
  "gatewayPublicKey": "<публичный ключ AWG gateway в Base64>",
  "server": "185.251.89.19",
  "port": 51821,
  "number": 4,
  "parameters": {
    "Jc": "3", "Jmin": "40", "Jmax": "80",
    "S1": "17", "S2": "29", "S3": "3", "S4": "9",
    "H1": "1001-1010", "H2": "2001-2010",
    "H3": "3001-3010", "H4": "4001-4010",
    "I1": "<b 0x11223344><r 16>"
  }
}
```

Параметры выше — синтетический пример, не конфигурация действующего gateway.
Использовать согласованные J/S/H/I и публичный ключ фактического AWG gateway.
Схема не принимает PSK, privateKey, команды, пути или произвольный UAPI.
Все значения parameters — строки; J/S/H обязательны, I1..I5 необязательны.

Офлайн, из корня репозитория с зависимостью cryptography:

```sh
python -m scripts.activate_windows_awg \
  --key /secure/activation-signing.key \
  --profile /secure/public-profile.json \
  --request 'FC1-<64_HEX_СИМВОЛА>' \
  --sequence 1 \
  --output /secure/device.fcawgactivation
```

Подписывающий ключ должен соответствовать доверенному activation.pub клиента;
не путать его с ключом каталога обновлений. Issuer создаёт только новый файл,
срок импорта — сутки. Следующая изменённая активация требует большего sequence.
Уже импортированный профиль работает офлайн после срока импорта.
Ключи подписи/закрытые ключи/активации хранить вне Git, CI и журналов.

## Windows

Выбрать AWG → импортировать .fcawgactivation → подключить. WG-активация для AWG
не нужна. Для ручной смены транспорта: отключить → выбрать WG/TCP/AWG → подключить.
Во время подключения основная кнопка отменяет запуск. Другой Windows-пользователь
не может остановить или заменить занятую сессию.

Служба проверяет подпись, привязку к устройству и sequence, хранит активацию
в LocalSystem DPAPI. Движок и Wintun проверяются по закреплённым SHA256 перед
запуском. Конфигурация передаётся в stdin после назначения JobObject. AWG UAPI
listener отсутствует. Рабочие IPv4/IPv6 split routes и DNS/NRPT принадлежат сессии.

Общий с TCP журнал tcp-session.json содержит имя fcawg-адаптера и AWG number;
старые TCP-журналы совместимы. Внутренняя метка NRPT FamilyConnect TCP и коды
tcp-* сохранены для общего механизма. Это не означает использование TCP в AWG.
После сбоя движка/health: очистка, до трёх повторов с задержками 15/30/60 секунд.
Остановка отменяет повторы; перезапуск службы очищает журнал без автоподключения.
При tcp-cleanup-required восстановить службу и проверить очистку; не удалять
журнал вручную. При awg-engine-missing установить проверенную сборку с AWG.

## Выпуск и откат

CI использует синтетический peer и только выделенные маршруты. Внешний gateway,
полный маршрут, production HTTPS health и физические устройства требуют отдельной
приёмки. Автоматического WG→AWG→TCP пока нет. Kill switch отсутствует.
Новый выпуск требует новой версии, platform CI, проверки скачанных артефактов
и офлайн-подписи каталога. Опубликованный desktop 0.2.9 не заменять этой сборкой.
Откат: отключить сессию, установить предыдущий проверенный installer; DPAPI-профили
сохраняются. При незавершённой очистке сначала восстановить сеть/службу.
