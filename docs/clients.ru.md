## Desktop parity106 — пока разработка

Native-бинарники amd64 уже собраны, но это внутренние компоненты
службы, **не пользовательские установщики**. Не заменяйте ими установленный клиент.
Изолированный Linux TUN/routing-тест не равен live MESH-приёмке.

В коде разработки также реализованы ограниченные readiness-квитанции и отдельный
аутентифицированный ACK. Есть локальные тесты, но не установленная/live-приёмка;
это не активирует компьютер заново и не выдаёт доступ к P1. Identity не изменяется.

RNS bootstrap-адаптер теперь использует принятый канал и упакованный изолированный
runtime RNS1.5.1. Проверен настоящий локальный обмен и завершение процесса, но это
не live desktop VPN и не разрешение P1. Для Windows ещё нужны bundled Python runtime
и broker-интеграция; пользователю не предлагается вручную устанавливать Python
или переносить компоненты в обход незавершённой штатной поставки.

Собран неподписанный offline-установщик системного Linux-компонента для разработки.
Он ещё не установлен/принят и не заменяет пользовательский установщик приложения.
Точный архив/SHA256 и RU/EN-инструкции — в отчёте; это не публичное обновление.
Нового установщика приложения пока нет. Сохраните существующую установку и её собственную
Device Identity; не копируйте ключи телефона, не удаляйте данные и не активируйте
компьютер заново ради этого переноса. Ссылки загрузки не изменены. Частный кандидат
требует проверки реальных ОС/TUN, интерфейса и обновления поверх прежней версии;
публикация — только отдельным решением. [Матрица и точные gates](releases/2026-10-23-desktop-parity106.md).

В рабочем дереве GTK ручной MESH уже связан с системной службой и доступен только
при наличии проверенного установленного компонента. Настройки разделяют выбранный
и фактически согласованный профиль; Disconnect отменяет восстановление службы.
При закрытии окна явно сообщается, что MESH продолжает работать в службе. Это код
и UI-проверки с подставными сетевыми состояниями, не установленный/live-VPN PASS
и не рекомендация заменять стабильное приложение. Эталон Android снимался только
в новом эмуляторе без сети, неизменённый телефон не использовался.

### Диагностика в сборке разработки

В настройках GTK разработки появился раздел **О приложении / Диагностика**.
**Обновить Support ID** запрашивает ID именно этого компьютера через действующую
аутентификацию; **Копировать Support ID** копирует только ID, не ключ. При ошибке
обновления сохранённый корректный ID остаётся. **Отправить диагностику** сначала
объясняет состав данных, затем **Сохранить JSON** открывает системный диалог.
Передайте файл выбранному получателю самостоятельно: автоматической загрузки нет.
Shell/root и отключение VPN не нужны. В JSON — ограниченные состояния, публичные
счётчики/коды и счётчики пропусков; сайтов, сообщений, адресов и ключей нет.
Это проверенные локально функции рабочего дерева, не опубликованное обновление0.2.11.
Windows-эквивалент, установленная сборка и полный паритет диагностики ещё не приняты.

### Мессенджер в рабочем дереве

Раздел GTK **Чаты** теперь использует общее зашифрованное хранилище вместо
заглушки. Сначала активируйте этот компьютер, затем выберите **Начать общение**.
Отдельная chat identity не копируется с Android. Ключ истории32Б хранится в
системном Secret Service пользователя; может потребоваться разблокировка связки
ключей. Отсутствие/повреждение ключа или истории вызывает ошибку, а не создание
новой identity. Для обновления нельзя удалять запись связки ключей или каталог чата.

В **Добавить контакт** вставьте полный публичный ключ и независимо сравните весь
отпечаток перед сохранением. Есть переименование контакта, очередь текста,
редактирование и сохранение зашифрованной истории после повторного открытия.
**Принято узлом** не означает сохранение у получателя: для этого проверяется
отдельное подтверждение. Linux mailbox сначала использует обычную маршрутизацию
ОС (SYSTEM), в том числе существующий VPN, без привилегированных обходных маршрутов.
Новый согласованный root-компонент также даёт ограниченный chat-only доступ через
действующий аутентифицированный MESH (EXISTING_EXIT), проверяя компьютер и UID.
Отказ авторизации или конфликт не разрешает fallback. Это локально проверенный код,
не установленная/live-приёмка. Защищённый underlying DIRECT, service-only без VPN,
приёмка установленной фоновой службы и полный интерфейсный паритет ещё не закончены.
Это исходники разработки, не
опубликованный установщик и не подтверждение работы через рабочий сервер.

Пункт **Мессенджер EXIT** в чатах открывает настройки фоновой доставки и уведомлений;
они сохраняются в зашифрованной истории. При включённом фоне доставка продолжается
после выхода из GUI в непривилегированной пользовательской службе, не root-helper VPN.
Отключите фон здесь, чтобы остановить доставку без открытого активного чата.
После закрытия GUI с отключённым фоном простаивающая служба завершится примерно за36с.
Служба не создаёт новый чат и не обходит заблокированную/отсутствующую связку ключей;
запускается при использовании приложения, не как новый общесистемный сервис при загрузке.
Существующий чат возобновляется
при запуске без замены ключей и создания новой identity при ошибке. Уведомление ОС
не содержит текст/аудио/имя контакта; нажатие открывает проверенный разговор.
Прочитанными становятся показанные сообщения в активном окне. Ошибка или отсутствие
службы уведомлений не помечает сообщение уведомлённым. Подтверждение службы не
доказывает показ всплывающего окна: например, режим «Не беспокоить» может его скрыть.
Системные настройки уведомлений сохраняют силу. Раздел сервисных сообщений показывает
объявления для Linux, тип, редакцию, срок и автора; при ошибке обновления остаётся
сохранённая история. Объявление не запускает команды и не устанавливает обновления.
В локальном Linux-кандидате меню **⋮** открывает управление объявлениями. Сервер
заново проверяет существующую identity этого компьютера при просмотре, публикации
и правке; обычный пользователь не может выдать себе роль. Заполните заголовок и
текст, откройте **Предпросмотр объявления**, затем явно подтвердите публикацию.
Новое объявление предназначено всем трём платформам на30 дней; правка сохраняет
автора, аудиторию и срок. При конфликте откройте последнюю редакцию заново.
Если ответ потерян, повтор из того же предпросмотра использует ту же identity
операции, а не создаёт второе объявление. Рабочие роли не выдавались и объявления
в рабочем сервисе не отправлялись. Реальная служба уведомлений/установленный пакет
и точное сравнение Android-экранов управления ещё требуют приёмки.

Если ответ службы на отправку потерян, сначала проверьте историю разговора:
сообщение могло уже сохраниться. Автоматического повтора неоднозначной операции нет.
Обычное обновление должно сохранять и каталог чата, и запись связки ключей.

Голос: удерживайте кнопку микрофона; движение влево отменяет запись, вверх
закрепляет её. Активация с клавиатуры начинает закреплённую запись. Остановка
или отпускание открывает предпрослушивание, **не отправляет автоматически**.
Можно прослушать, поставить на паузу, перемотать и затем нажать «Отправить».
Escape и уход из разговора отменяют неотправленную запись. Лимит60 секунд;
временные аудиофайлы не создаются. «Голосовой профиль» по умолчанию Opus;
Codec2 требует отдельного подтверждения поддержки у контакта. Это не выдаёт
доступ к VPN/P1 и не заменяет проверку fingerprint. Выбор хранится зашифрованно.
Нужен системный GStreamer и Codec2. Проверки используют синтетический микрофон
и беззвучный выход; физический микрофон/наушники и реальная пара с Android NOT_RUN.
