# Подписанная доставка TCP-компонента

Реализован отдельный операторский путь fetch/install из доверенной копии репозитория.
TCP 0.1.0 и подписанный каталог sequence 1 опубликованы и проверены через HTTPS.
Операторский CLI пока не включён в установленный клиент.
Шесть файлов обычного Linux updater остаются прежними.

## Доверие и каталог

Ed25519, публичный anchor clients/desktop/update.pub; домен подписи
`family-connect/tcp-component/v1\0` отделён от app-update. Schema 1 содержит component=tcp,
architecture=amd64, независимые version/sequence, issued_at/expires_at (не более 90 дней)
и artifact {url,size,sha256}. URL фиксирован по версии:
`https://github.com/Joker20380/family_connect/releases/download/tcp-vVERSION/FamilyConnect-TCP-amd64-VERSION.tar.gz`.
Каталог опубликован в updates/tcp-pilot.json. CLI не принимает новый
anchor из сети или из архива. Проверяющий код и anchor должны быть заранее доверенными;
не запускать скачанный из того же непроверенного комплекта verifier с sudo.
Операторская установка из checkout не заменяет будущую доставку root-owned broker.

Каталог ограничен 64 KiB, архив 128 MiB, распаковка 128 MiB + 64 KiB метаданных.
Проверяются подпись, срок, архитектура, поля, размер и SHA256. Загрузка только HTTPS,
с запретом перехода на HTTP и ограничениями времени/размера. Повторная проверка
срока перед сохранением и установкой. Tar допускает только девять известных обычных
файлов; ссылки, дубликаты, чужие пути и чрезмерная распаковка отклоняются.

Отдельные закрытые state каталоги:

- fetch: ~/.local/state/family-connect-tcp-updates;
- root install: /var/lib/family-connect-tcp-updates.

Сохраняются sequence, digest каталога, version, artifact SHA256 и last_now. После
перезапуска отклоняются откат счётчика/версии/часов, другой каталог с тем же sequence
и другие байты той же версии. Продление срока возможно новым sequence при тех же
version/байтах. Первое доверие опирается на anchor и срок; локальный floor защищает
после первого принятия. Удаление state администратором сбрасывает эту историю.
Floor продвигается при принятии каталога, даже если загрузка/установка затем не удалась;
повтор того же каталога разрешён. Пользовательский floor не считается root-доверием.

## Операторские команды после выпуска

Из заранее доверенного checkout (Python 3 + cryptography):

```sh
python3 scripts/tcp_delivery.py fetch
sudo /usr/bin/python3 -I scripts/tcp_delivery.py install --catalog /absolute/path/catalog.json --archive /absolute/path/archive.tar.gz
```

fetch печатает путь к проверенному архиву, catalog.json сохраняется рядом. Можно подать
локальный каталог через --catalog: подпись обязательна независимо от способа доставки.
Это пока CLI, без кнопки в GTK и без автоматической установки. Root повторно проверяет
подпись и однократно читает архив; распаковывает проверенный снимок в root-private
каталог и запускает только его install.py. Установщик сохраняет backup и выполняет
daemon-reload; профиль не импортируется и VPN не запускается. installed.json пишется
только после успешного завершения, временная распаковка удаляется и при ошибке.

Откат компонентов выполняется из backup/restore.json по [runbook](linux-tcp-install.ru.md).
Для исправляющего публичного выпуска использовать новую версию/sequence, не заменять
старые бинарники и не удалять anti-rollback state ради установки старого каталога.
Отказ питания/тайм-аут процесса всё ещё требует проверки состояния компонентов/backup;
добавление подписи не делает существующий установщик crash-atomic.

## Порядок выпуска

1. Провести remote CI для итоговой ревизии, скачать собранный компонент, проверить hash
   и установку; перед широким rollout остаётся отдельная VM/оборудование.
2. Подготовить неизменяемый TCP release/version и архив с указанным выше именем.
3. Только после этих проверок подписать локально существующим offline Ed25519 ключом:

```sh
python3 scripts/sign_tcp.py --key /absolute/private/ed25519.key --archive /absolute/verified/FamilyConnect-TCP-amd64-VERSION.tar.gz --version VERSION --sequence SEQUENCE --output /absolute/new/tcp-pilot.json
```

4. Проверить каталог через verifier, опубликовать архив и каталог, выполнить настоящее
   HTTPS fetch/install. Затем интегрировать доверенный broker/bootstrap и UI клиента.

sign_tcp.py не перезаписывает output; sequence выбирает оператор по истории публикаций.
Рабочий private key не должен попадать в CI/сервер/Git. Сам signer не проверяет результаты
CI: это обязательный операторский release gate. Первичная проверка использовала временный тестовый ключ.
После CI/приёмки TCP 0.1.0 подписан production key локально; [отчёт](releases/2026-09-11-tcp-release.ru.md).


## Системный установщик и кнопка Linux-пилота

Из заранее доверенного checkout администратор один раз выполняет:

```sh
sudo /usr/bin/python3 -I clients/linux/install-tcp-updater.py
```

После этого `--awg-pilot` показывает «Установить / обновить TCP». Отключить VPN,
нажать кнопку, подтвердить действие и системную авторизацию. Root-owned broker сам
загружает фиксированный подписанный каталог и архив; GUI не передаёт ему пользовательские
пути/URL. Без bootstrap доступна инструкция о необходимости настройки администратором.
Публичный TCP 0.1.0 устанавливается без запуска VPN. Кнопка не входит в установленный
stable Linux 0.2.7; доступна в исходном pilot launcher после перезапуска.
На ноутбуке bootstrap и реальная установка через кнопку проверены; [отчёт/откат](releases/2026-09-11-tcp-updater.ru.md).
Bootstrap на новые машины пока доставляется оператором из доверенной копии, не самим
подписанным TCP-архивом. Сам verifier/anchor не заменяются TCP component install.
