# Системные сообщения из панели

Функция в исходниках; установленная панель пока не обновлена. Вход — прежний
аккаунт панели. Права `console.view_system_messages` и
`console.send_system_message` выдаются раздельно; существующий superuser имеет оба.
Автоматического назначения прав обычным операторам нет.

1. Откройте «Системные сообщения» → «Новое объявление» (`/system-messages/`).
2. Укажите заголовок (160 UTF-16 единиц), текст (4000), тип, платформы и срок1–365 дней.
3. Нажмите «Предпросмотр — без отправки». Сохранённые текст/аудитория/ID неизменяемы.
   Для другого текста откройте новую форму, но не делайте этого при неизвестном
   результате уже отправленного запроса.
4. Проверьте весь текст и **общедоступную аудиторию**, отметьте подтверждение,
   отправьте на публикацию. Это не адресное сообщение только своему телефону.
5. Внешний publisher обрабатывает очередь. Повторный клик не создаёт второй запрос.
   При неизвестном результате используйте «Повторить с тем же ID» в прежней карточке.

Тексты общедоступны в существующей HTTPS-ленте. Не помещайте туда личные сведения,
ключи или диагностические профили. Платформа — фильтр отображения, не контроль доступа.
Список показывает последние100 запросов этой панели; объявления из Android/CLI не
импортируются в историю панели. Автор в клиенте — имя серверного publisher-разрешения;
аккаунт, подтвердивший публикацию, отдельно фиксируется в аудите панели без тела текста.

## Статусы и границы

- Предпросмотр: ничего не отправлено.
- В очереди: durable-запрос сохранён; без отдельного publisher он остаётся локальным.
- Опубликовано: API подтвердил ID, а отдельный GET публичнойv2-ленты вернул тот же
  живой текст/аудиторию/срок. Это **не** ACK доставки и не «прочитано».
- Результат неизвестен: возможна уже совершённая публикация; повтор только с прежним
  ID/текстом. Автоматических повторов этого состояния нет.
- Отказ: сервер отказал либо права оператора отозваны до выполнения. Исправьте
  полномочия, затем при необходимости явно повторите неизменный запрос.

Клиенты получают объявление при успешном обновлении ленты; offline не означает
немедленную доставку. Ответы не поддерживаются. Личный двусторонний чат — отдельная
функция поддержки; эта лента не требует служебной chat identity или новой Android124.

## Подключение publisher после допуска обновления

Сначала review/merge/CI, свободное место, свежий backup PostgreSQL/конфигурации и
проверка восстановления в отдельную БД. Миграция0013 аддитивна, пользователей не меняет.
В рабочем registry оператор создаёт **отдельный отзываемый токен только объявлений**
существующей командой `scripts.service_notices grant`. Никакие ключи телефона не нужны.
Не выдавайте publisher-токен web-контейнеру и не добавляйте его в `.env` панели/Git/CI.

Внешний доверенный процесс использует этот же проверенный source/runtime и доступ
к локальной БД очереди. Передавайте секрет только путём к обычному файлу0600 владельца
процесса. Разовый запуск (пути — пример, не существующие credentials):

```sh
python manage.py publish_system_messages \
  --origin https://185.251.89.19:8443 \
  --token-file /private/system-publisher.token --limit 1
```

Команда выполняется из `control_plane/`, с приватными настройками подключения к
локальной PostgreSQL, не с production registry/SSH-доступом. HTTPS-проверка сертификата
обязательна; redirect/proxy не используются. Успех проверяется публичным GET без
Authorization. Ограничение1–20 запросов за запуск; процесс заново проверяет права
создателя перед каждой публикацией. Два worker не берут одну строку одновременно.
При падении процесса транзакция очереди откатывается, повтор сохраняет ID.
Таймер не устанавливается автоматически. Не включайте его до проверки очереди.

Для отключения остановите внешние запуски и отзовите publisher-токен. Для отката UI
верните прежний image, **не** восстанавливайте устаревшую БД и не удаляйте таблицы/volumes.
Уже опубликованный текст не отзывается откатом панели: он остаётся до срока/отдельного
действия существующего администратора объявлений. Для проверки только на своём аккаунте
сначала используйте изолированный стенд, а не публичную ленту всех пользователей.
