## Исправление tools

Первый adverse-condition прогон остановился: ContentPaddingAddition=65536 принят,
хотя tools хранит параметр в u16 range. В pinned src/type.c обе границы сравнивались
с UINT32_MAX, после чего u16_range_init усекал значения. Это не безопасный отказ:
выбранное пользователем значение может превратиться в другую настройку.

[Локальный patch](../../pilot/awg31/patches/0002-tools-u16-range.patch) использует
UINT16_MAX и отвергает знак, пустую верхнюю границу и недопустимый начальный символ.
[C regression](../../pilot/awg31/tools_regression.c) на неизменённых tools падает
на65536; с patch проходит12 отрицательных случаев и round-trip0/65535/0–65535.
Он также запускается в Docker build перед сборкой awg. Старый u32 parser не менялся;
это не полная приёмка всех синтаксических конструкций upstream.

## Сценарии

lab.py --resilience: два isolated namespaces, MTU1280, netem35ms/20mbit на сторону,
AWG base, GOMAXPROCS1 на engine. Это не общая квота1CPU и не Amsterdam capacity test.
Проверяются:

- Отказ S1=11 с HeaderProtectionKey и отказ ContentPaddingAddition=65536.
- Неверный HeaderProtectionKey: нет доставки и latest-handshakes=0 за cold probe1с;
  затем возврат правильного профиля и положительная проверка доставки.
- Несовпадение H4: нет доставки; восстановление после возврата конфигурации.
- Tunnel MTU1280 и1200: DF ping payload1252/1172 проходит, на1 байт больше локально
  отклоняется с message too long. Это проверка границы интерфейса, не PMTUD blackhole.
- Заданные случайные потери1% независимо на каждом направлении; передача1MiB TCP,
  проверка каждого байта и полного размера. Seed не закреплён; это не фиксированная
  доля потерь прикладных сообщений. Скорость короткого потока не сравнивать с8MiB baseline.
- Краткий blackhole100% потерь, восстановление после удаления netem loss.
- Client interface down/up; отдельный restart server engine с восстановлением
  interface/config, ожидание первого успешного ping.
- Ускоренный RekeyAfterTime5с/RejectAfterTime30с: по трафику наблюдается увеличение
  latest-handshakes; затем возвращён исходный профиль. Стандартные долгие интервалы
  и многочасовая работа этим не приняты.

## Предварительные отказы сохранены

1. Исходный tools принимал65536. Исправлен patch и подтверждён C/runtime regression.
2. Восстановление H4 не уложилось в15с. В отдельном повторе измерено15.1186с в окне30с.
   Увеличение окна наблюдения не является исправлением задержки и не закрывает15s SLO.
3. Harness предполагал код2 от ping при слишком большом пакете. Проверка исправлена
   на ненулевой код и явное message too long из stdout/stderr; следующие прогоны
   проверяют именно локальный отказ, а не произвольный таймаут доставки.
