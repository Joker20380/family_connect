# 5.3а: локальная управляемая выдача AWG3.1

24.09.2026. Первый checkpoint5.3а; этап не закрыт. Production rollout отсутствует.
Android0.1.18-beta50/code50, Linux0.2.10 и Windows0.2.13 не перевыпускались.

## Изменения

`provisioning.configuration.TransportProfile` принимает AWG3.1 через существующий
строгий parser с явным allow_awg31. Обязательны HeaderProtectionKey,
ContentPaddingAddition, RandomTrailers и DisableCookies плюс полный базовый набор AWG.
Проверяются ключ, padding, флаги и совместимость защищённых заголовков. Профиль3.1
нельзя принять как2.0 с потерей параметров. Hooks/неизвестные поля запрещены.

`ConfigVerifier(..., supports_awg31=True)` позволяет проверять такой конверт только
после явного включения способности на доверенной стороне приложения. По умолчанию
сохраняется UNSUPPORTED_TRANSPORT_VERSION. Один client_version не доказывает наличие
native engine. Сетевое значение из профиля не должно включать эту способность.
Подпись/recipient/WG binding/срок/minimum version проверяются как прежде.

FleetPublisher теперь может выпустить профиль3.1 для ready lease с операторскими pins
через существующие schema2/domain/Ed25519 authority. Сохраняются шифрование per-device,
локальная подстановка приватного ключа и повторная выдача тех же bytes.
Новая подпись доверия, wire schema и DB migration не вводились.

Добавлен отдельный immutable corpus `tests/vectors/control-awg31-v1`: восемь
подписанных примеров с заранее заданными результатами для способного и legacy verifier.
Покрыты положительный профиль, отсутствие защиты, неверный padding, несовпадение gateway,
ложная метка2.0, срок, старая версия и повреждённая подпись. Manifest содержит hashes.
Ключи исключительно публичные тестовые, получены из явных TEST ONLY labels;
генератор не читает deployment keys и пишет только в новый каталог.
Прежний corpus `control-v1` не менялся. Native runners ещё не подключены к новому набору.

## Проверки

Расширенный прогон16 файлов:356 passed; два теста первоначально заблокированы
песочницей на создании локального сокета. Оба повторены вне песочницы:2 passed за6.30с
(`test_real_rns_complete_lifecycle`, `test_extracted_preview`). Это локальный RNS,
а не внешняя сеть и не тест работоспособности в России.

Затем добавлены два сценария AWG3.1 journal: commit/retry после открытия durable state
и rollback при отрицательной health-проверке. Финальный прогон двух новых файлов:
36 passed за0.40с. Итого360 уникальных сценариев прошли по совокупности запусков,
не один общий прогон360. Journal использует тестовую application boundary.

В проверках реальный FleetStore/issuer/encryption/verifier, новые gateway IDs,
сохранение всех параметров и локального device key binding. Ошибочные параметры,
неполный профиль, downgrade label, legacy клиент и истёкший lease отвергаются.
Секретный production signer не читался; новые файлы не включены в runtime packaging.

## Оставшаяся работа и откат

Native Android/Windows managed verifier пока отвергают3.1; Linux managed runner также
не включает новый capability. Нельзя объявлять managed3.1 установленным или выдавать
его действующим клиентам на основании этого checkpoint. Нужно подключить corpus к
native runners, проверить platform parsers/apply/health/rollback и capabilities,
согласовать minimum versions и выпустить клиенты по обычным release gates.
Предыдущая native-приёмка gateway engine не заменяет managed end-to-end приёмку.

5.2 ACK/offline→online/access migration остаётся открыт. Приняты требования усиления
[устойчивости](../blocking-resilience.ru.md), включая independent ingress и сегментацию;
они здесь не реализованы. Следующий шаг — native совместимость5.3а.

Серверный откат не требуется. Для локального пилота capability оставить выключенным,
прекратить новую выдачу3.1; не откатывать DB/revision floors и не менять старые
подписанные bytes. Live миграция и её rollback должны быть приняты перед внедрением.
