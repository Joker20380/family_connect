# Синхронизация мессенджера по событиям — 13 сентября 2026

Добавлен messenger.sync.SyncController для существующего Mailbox.sync на
RNS1.5.1/LXMF1.1.1. Это библиотека жизненного цикла, ещё не подключённая к Android.
Она получает online/foreground от вызывающего приложения и запускает ограниченное
получение почты только при наличии сети и открытом приложении. Переходы состояния
вызывают синхронизацию; повтор неизменного состояния не вызывает новый запрос.

## Поведение и компактность

Один worker и один объединённый pending event. Нет таймера периодического polling:
завершение запроса само по себе не планирует следующий. Явный request_sync подходит
для обновления пользователем, уведомления о новой почте или замены сетевого пути
при неизменном online=True. События во время работы объединяются максимум в один
последующий запрос. Online — сигнал ОС, не доказательство доступности relay.

Интервал между окончанием попытки и следующей — минимум30с по умолчанию.
После ошибок:30/60/120/240/300с, максимум300с; новая попытка только при наличии
нового события. Смена foreground/online не обходит интервал. Это не бесконечный
автоматический retry. Успех сбрасывает счётчик ошибок. Операция Mailbox ограничена
12с по умолчанию (до30с), прежними10 сообщениями/48KB и commit-before-purge.
Если почты больше10 сообщений, нужен следующий явный запрос/событие; автоматическое
вычитывание всего mailbox пока не реализовано. Outbox этим controller не отправляется.

Потеря сети или уход в фон отменяет текущую попытку; поздний результат прошлого
поколения не публикуется как результат новой сессии. Уже сохранённая почта не
откатывается. При отмене до purge ciphertext остаётся на узле и при повторе
распознаётся как дубликат. Контроллер не владеет Store и не закрывает его.
Перед закрытием Store нужно вызвать close и получить True. False означает, что
worker ещё завершает работу; следует сохранить Store открытым и повторить join.
Close запрещает новые события и скрывает запоздалый результат. Ошибки не раскрывают
пути хранилища или текст сообщений. Источник lifecycle-событий должен быть доверенным.

## Проверки

Детерминированные проверки с блокируемым mailbox: нет запроса в фоне;100 refresh
событий объединяются в один повтор; после обработки очередь не опрашивается;
отмена при потере сети, возобновление, отбрасывание старого результата; ошибка
не вызывает самостоятельный retry; череда online/offline не обходит backoff;
close отменяет worker, отказ от новых событий и корректный False при незавершённом
join, затем подавление позднего успеха. Проверены некорректные пределы.

Реальный обмен между тремя локальными RNS-процессами: письмо остаётся в spool,
пока получатель в фоне; foreground доставляет/сохраняет/удаляет одно письмо;
20 повторных одинаковых lifecycle-событий не добавляют запросов (attempts=1).
Все private identity синтетические. Работа ОС Android/Doze этим не проверена.

Полный набор:51 passed за71.64с. После финальной правки close (очистка
результата) и добавления проверки позднего успеха: все10 sync tests passed за3.29с.
Эти10 пересекаются с общим набором, результаты не суммируются.

Воспроизведение: pinned provisioning/requirements.lock и messenger/requirements.lock,
`python -m pytest messenger/tests/test_sync.py -q`;
полный набор: `python -m pytest messenger/tests -q`.

## Интеграция и откат

Пример для владельца жизненного цикла:

```python
controller = SyncController(mailbox)
controller.update(online=True, foreground=True)
# Upon background / connectivity loss:
controller.update(foreground=False)
# Before closing the chat Store:
if not controller.close():
    # Retain Store; await shutdown again before releasing its resources.
    raise RuntimeError("Sync worker still stopping")
```

Никаких новых полей wire-протокола, APK, server deployment, изменения AWG или
Android lifecycle callbacks. Служба Amsterdam остаётся на предыдущем коде.
Библиотека использует прежний mailbox API. Commit [skip ci] сохраняет паузу сборки;
remote CI не заявляется. Откат: убрать вызовы SyncController и вернуться к явному
Mailbox.sync; предыдущее состояние исходников4f0074958198620f7ce844e5196f6cd7c0d510ec.
