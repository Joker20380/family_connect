## Реализация и исправленный сбой

Один `libfc-awg.so` обслуживает WG без AWG-параметров и AWG2 с J/S/H/I.
WG сохраняет прежние `profile.enc` и AndroidKeyStore alias; AWG получает отдельные.
Импорт/удаление одного протокола не затрагивают другой. Переключение требует
остановки; ошибка очистки оставляет доступной повторную остановку.
Состояние «подключено» означает поднятый интерфейс, без обещания доступности Интернета.

[Android backend](https://github.com/amnezia-vpn/amneziawg-android/tree/5420011143f9dd42831cc95fcdb0d6ac9bde868f)
и [движок](https://github.com/amnezia-vpn/amneziawg-go/tree/1cc94272ca8e9e223a5fe76382f5880f09d3c12d)
закреплены; Go1.26.1, NDK28.2.13676358; arm64-v8a/armeabi-v7a/x86/x86_64.
Сборщик исключает root backend, публичный UAPI и сигнальный дамп стеков;
лог движка выключен, JNI handles синхронизированы, ошибки конфигурации закрывают
устройство, результат защиты UDP-сокетов проверяется. Лицензии и manifest
включены в APK. Побитовая воспроизводимость разных сборок не заявлена.

Два отдельных Go runtime давали SIGSEGV на повторном WG после AWG
(CI34658624840, Zygote signal11). Это согласуется с
[известным ограничением Go на Android](https://github.com/golang/go/issues/73841);
точный native stack не получен. Один runtime устранил воспроизводимый сбой.
Исходный зелёный шаг CI34657442748 ошибочно скрывал failure через tee;
теперь Python сохраняет вывод Gradle и передаёт код ошибки. Appops deny не отзывал
активный VPN; вместо него принят настоящий системный диалог. Для UI automation
включён FLAG_REPORT_VIEW_IDS. Перед передачей снято сохранённое ACTIVATE_VPN:
одна передача сама по себе отзывает текущую сессию, но сохраняет право будущего
подключения. Неуспешные прогоны не считаются приёмкой.
