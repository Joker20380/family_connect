# Windows TCP: восстановление после падения движка — 2026-09-11

Следующий пункт этапа 4: установленная TCP-сессия автоматически восстанавливается
после неожиданного завершения Xray. Служба сначала закрывает процесс/JobObject и
очищает собственные маршруты/DNS/NRPT по журналу; только после успешной очистки
ждёт 15, 30, 60 секунд и повторно выполняет preflight с новым адаптером и текущим
uplink. Не более трёх повторов на одно явное «Подключить», без сброса счётчика
после удачного восстановления. Начальная ошибка настройки не запускает повторы.

При ожидании/повторе status=pending, error=tcp-reconnecting, transport=tcp;
GUI показывает восстановление и оставляет отмену. SID-владелец сохраняется.
Успех очищает ошибку, исчерпание лимита даёт tcp-recovery-exhausted и ручной повтор.
Отмена/Disconnect и остановка службы прекращают повторы. Ошибка очистки сохраняет
журнал и tcp-cleanup-required, повтор запрещён. Падение самой службы по-прежнему
восстанавливает сеть при SCM restart, но не запускает VPN заново. Закрытие GUI
оставляет службу и её ограниченные повторы работать, как указано в подтверждении.

## Проверки

Локально: синтаксис Python harness и git diff --check. Windows runtime CI ожидается.
Изолированный LocalSystem CI расширен: повтор после engine crash с реальными
IPv4/IPv6 HTTP и OS DNS, отмена/stop службы во время backoff, три повтора и
исчерпание лимита после четырёх падений, проверки владельца во время ожидания,
сохранение default routes/DNS/NRPT. Используются настоящие паузы 15/30/60 секунд.
UI: 336 макетов плюс переходы восстановления/успеха/исчерпания и ручной повтор.

## Границы и дальнейшая работа

Это восстановление после завершения процесса, не health-monitor интернета:
живой Xray с недоступным сервером пока не обнаруживается. CI использует локальный
синтетический VLESS и ограниченные маршруты/DNS; внешний REALITY, физическая смена
сети и полная маршрутизация ещё не приняты. WFP/kill switch отсутствует: во время
очистки и пауз могут использоваться обычные маршруты. Новых сетевых тестов на
пользовательских устройствах, нагрузочных испытаний или изменений gateway нет.

Далее health-monitor/recovery и full-routing acceptance, затем Windows AWG,
Android transports и этап 5 Reticulum. Android update/Google Play остаются отложены.

Версии не менялись: опубликованный desktop0.2.9/source42f9d32/catalogseq8,
Linux установлен0.2.7, последний подтверждённый Windows0.2.7; сервер0.2.1,
TCP component/Setup0.1.0. CI installer0.2.9 — preview, существующий релиз не заменять.
Распространение: отдельная приёмка полного маршрута, новая версия и platform CI,
проверка артефактов/офлайн-подпись каталога. Возврат: остановить VPN и установить
предыдущий проверенный installer, профили сохраняются. При cleanup-required сначала
[восстановить сеть по журналу](../windows-tcp-session.ru.md), не удалять его вручную.
