# Мессенджер: уведомления, события и имена — 2026-09-23

## Причина и изменения

Ранее ChatActivity владела историей и получением; onStop закрывал владельца,
а опрос выполнялся только при открытом экране. Системных message notifications не было.

Новый ChatRuntime сериализует работу UI и фоновой службы с одним владельцем Store.
ChatDeliveryService показывает явное уведомление, не зависит от открытого экрана,
возобновляется после обновления/перезагрузки при включённой настройке. Foreground
polling сохраняется, если пользователь выключил только фоновое получение.

Два канала: личные сообщения и события Family Connect. PendingIntent открывает
диалог; занятый экран обрабатывает переход после завершения операции. Текст личной
переписки не показывается в уведомлении/на экране блокировки. Непрочитанные и
уже показанные сообщения отмечаются раздельно в зашифрованном Store. Старая история
при миграции помечается прочитанной; повторы сообщений не создают повторную историю.
Входящие одного диалога группируются в одно уведомление со счётчиком.

Имена задаются через меню диалога → «Переименовать чат», хранятся зашифрованно,
показываются в списке, заголовке и уведомлениях. Ключ и fingerprint не меняются.
Имя только локальное; пустая строка восстанавливает стандартное отображение.

Личные сообщения используют прежний RNS mailbox и привязку сокета к основной сети.
Регистрация мессенджера и HTTPS-лента также обходят VPN, не меняя обычный путь
активации/получения VPN-конфигурации. Это не доказывает независимость control ingress
этапа5 и не закрывает отказ единственного доступного endpoint.

## Администраторы и сервер

Владелец назначает/отзывает отдельные publishing credentials через операторский CLI.
Реестр0600 хранит SHA256 токенов; каждый администратор публикует через HTTPS API.
Автор фиксируется сервером. Стабильный id делает повтор запроса идемпотентным;
изменение содержимого под старым id отвергается. Отзыв блокирует новые публикации.
Срок действия, платформы, размер ленты и число объявлений ограничены.

RU185.251.89.19: добавлен `/friends/notices/publish` в существующий loopback API
и публичная пустая `/downloads/family-connect-events-v1.json`. Владелец Owner
создан; credential хранится приватно на сервере, не в Git/CI/выводе команд.
**Объявлений пользователям не отправляли.** Ранее выданные VPN/чат-ключи не меняли.
Лента — публичные служебные тексты, а не E2E-переписка. Доверие — фиксированный
HTTPS origin/проверка сертификата; отдельная offline-подпись событий не реализована.
Сообщение не применяет настройки сервера и не устанавливает обновление.

Server smoke: feed HTTP200/пустой; anonymous publish HTTP403;
старый challenge route HTTP400 на невалидный запрос. API service active.
Изменён только invitation API и ingress-конфигурация; VPN-службы не перезапускали.

## Оставшаяся приёмка и глобальный план

Основной незавершённый этап **4: клиенты и согласованный стабильный выпуск**.
Этапы1–3 дают рабочий VPN-пилот, но устойчивость/российская сеть остаются открытыми.
Этап5 частичный; этап6 — сквозное восстановление при полной недоступности gateway —
не закрыт. В этапе7 начаты сервисные события; оплаты/подписок нет.
Мессенджер Android получил новый приоритет по прямому указанию пользователя;
это не отменяет долгов VPN-приёмки. Windows/Linux messenger UI ещё не реализован.

Нужны: два телефона в фоне, длительный сон/Doze и разные OEM, запуск после реальной
перезагрузки, отказ/повторная выдача разрешения Android13+, проверка исчерпания квот,
точный platform CI и согласованный публичный выпуск. FCM не добавлялся; Android
может задерживать собственную службу во сне. После системного force-stop нужен
запуск пользователем. Beta35 остаётся публичной APK; update catalog не менялся.
