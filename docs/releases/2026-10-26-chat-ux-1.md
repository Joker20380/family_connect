## Before / after

Before: chat occupied the compact VPN dashboard; contacts were generic buttons,
messages plain rows, single-line entry scrolled with history, no built-in emoji UI.

After: one MessengerWindow in the same GTK application, default900×680. Navigation
and chat deep links reuse it; hiding/reopening retains the same ChatClient and drafts.
App shutdown uses the existing detach/close path. No second owner or messenger
process; hidden delivery is still governed by the existing user-service preference.
The VPN window no longer changes size to accommodate chat.

Adw.Leaflet provides the GTK4.8/Adw1.2-compatible adaptive equivalent of
NavigationSplitView: independent dialogue/history scrolls, wide split, narrow Back.
Loaded contacts have deterministic initials, name/last-message preview/time/unread
badge and selection. Service events are a separate row. Search is local only;
contacts load in batches of50. No downloaded avatars or profile photos.

Incoming/outgoing bubbles align left/right, text remains selectable, nearby messages
group, dates separate, outgoing statuses have compact accessible indicators and
exact existing status tooltips (no invented read receipt). Revisions show edited;
voice playback is inside the bubble, with existing explicit controls. Context-menu
editing uses the same RPC. History keeps existing50-message pagination/offset bounds.

Composer stays outside history scroll: multiline TextView, Enter/send and
Shift+Enter/newline, per-dialog draft retained on refusal/switch/hide, cleared only
after successful queue RPC. Native Gtk.EmojiChooser inserts at cursor/replaces
selection, restores focus and shares the4096-byte bound. Text, emoji/ZWJ sequences,
combining marks and whitespace are never normalized before signing/queueing.
Counter appears at3500 bytes. Emoji/voice/send have labels/tooltips and keyboard access.

Bounded onboarding separates activation→existing Settings, system component→existing
setup (visible pkexec), services→existing prepare-chat, and explicit local chat
creation. Locked keyring offers retry without reset. Ready card disappears. Transport
internals do not occupy the main chat view. Errors remain compact, not a replacement
for opened history. The new anchored layout required correcting voice gesture
coordinates for widget reflow; recording, codec and delivery semantics are unchanged.

## User guide / Краткая инструкция

**RU:** «Чаты» открывает отдельное окно; в узком окне вернуться к диалогам можно
стрелкой Назад. Введите сообщение, Enter отправляет, Shift+Enter переносит строку.
Кнопка эмодзи использует системный chooser; микрофон открывает штатную запись/
preview/send. Меню сообщения позволяет изменить свой текст. Меню списка содержит
свою карточку и настройки фоновой доставки/уведомлений. Административные шаги
в onboarding выполняются отдельно и только по явному нажатию.

**EN:** Chats opens the separate window; Back returns to the list on narrow layouts.
Enter sends, Shift+Enter inserts a newline. Emoji uses the system chooser. Microphone
opens existing record/preview/send controls. Use a message menu to edit your text;
the list menu contains your card and background-delivery/notification preferences.
Each administrative onboarding action is explicit and separate.

## Limitations / installation boundary

Drafts retain the existing in-memory lifetime; no new cross-process draft store.
The history API permits offsets0–1000: a last-message preview outside that bound is
not fabricated; the row says to open history. No global/network search, presence,
read receipts, reactions, replies, forwarding, stickers, media attachments or groups.
Adw.Leaflet is deprecated on newer Adw but preserves the supported older GTK baseline.
