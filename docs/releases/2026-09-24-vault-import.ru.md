# Импорт локального закрытого состояния в KeePassXC —24.09.2026

По поручению пользователя существующие локальные данные проекта скопированы в
зашифрованную базу.203 файла в2 архивных вложениях:7 signing/activation файлов,
196 файлов локального пилотного состояния. Приватный пофайловый manifest с SHA256,
размерами и методом копирования находится только внутри зашифрованных вложений.
Точные пути, ключи, приглашения, профили и пользовательское содержимое в Git не включены.

## Проверки и механизм

Мастер-пароль введён владельцем в локальном окне. Изменения выполнялись в отдельной
зашифрованной копии KDBX. Архивы создавались в памяти и передавались через memfd;
незашифрованный архив/экспорт на диск не записывался. SQLite-файлы снимались через
online backup API в память, WAL/shm отдельно не копировались. Статистика источников
проверялась на изменение во время чтения. Это не распределённый snapshot работающих
серверов и не доказательство согласованности независимых баз.

Первые попытки не заменяли базу: сравнение бинарного вложения после CLI --stdout
не прошло. На синтетическом binary fixture подтверждено изменение вывода CLI;
экспорт через файл memfd вернул точные исходные байты. После исправления оба реальных
вложения извлечены в память, SHA256 совпали. Затем db-info успешно открыл новую базу;
исходная KDBX проверена на отсутствие параллельных изменений, сохранена её локальная
зашифрованная копия, импорт атомарно заменил основную базу с fsync.

Все203 исходных файла сохранены.6 проверенных исходных корневых каталогов имеют0700.
Результат — проверенная зашифрованная копия, а не физическое перемещение или удаление
оригиналов. Локальный backup прежней KDBX не является внешней резервной копией.
Настройка памяти процесса не гарантирует отсутствие данных в swap/дампе всей ОС.

## Границы и продолжение

Серверные файлы, системный SSH agent, внешние аккаунты и чужие проекты не импортировались.
Root release key не помещался в CI или на сервер; теперь имеет дополнительную
локальную зашифрованную копию. Никаких новых подписанных выпусков не создавалось.

[План полного управления секретами](../secrets-and-recovery.ru.md): приватный реестр
потребителей → временная выдача секретов операторским инструментам → серверные
credentials вне checkout → офлайн-backup → устранение лишних plaintext копий.
.env допустим как формат закрытого runtime-конфига, но сам по себе не шифрует данные.
Существующие службы/скрипты не переводились на новые пути; это следующий этап.

Версии приложений/production прежние. Для отмены импорта сохранена предыдущая
зашифрованная KDBX; исходные файлы также сохранены. Откат не выполнялся.
Публикуются только этот отчёт, политика и статусы. Git-публикация проверяется отдельно:
предыдущая попытка52b5f6d получила Permission denied(publickey), коммит сохранён.
