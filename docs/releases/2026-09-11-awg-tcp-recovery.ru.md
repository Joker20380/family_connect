# Восстановление установленной AWG-сессии через TCP — 11.09.2026

Продолжение [установки TCP-helper](2026-09-11-tcp-host-smoke.ru.md), этап 3 roadmap.
Код приложения и helper не менялся; прежний исправленный TCP-helper остаётся установлен.

## Сценарий

На ноутбуке с новой Wi-Fi-сетью устанавливается AWG-соединение и проверяется интернет.
Собственная nftables table блокирует только IPv4 UDP к 185.251.89.19 на портах
51820/51821. Это endpoint/protocol fault injection, не блокировка всех IP-пакетов сервера.
TCP/443 остаётся доступен. Проверяются реальный backend.LinuxTCP и RecoveryPolicy:
интервал 15 с, два failed health cycles, recover со следующего транспорта цепочки.

Операторский harness вызывает привилегированные helpers из root-процесса; чтение
метаданных ограничено двумя тестовыми профилями владельца. Обычный пользователь joker
отдельно выполняет настоящую LinuxTCP.healthy. Это проверка backend/policy и real
network, **не end-to-end GTK/polkit acceptance**. Экран приложения и отмена диалога
авторизации этим тестом не проверяются. Автовосстановление продукта рассчитано на
открытое приложение; фоновая автономная служба этой серией не реализована.

Независимый root-owned watchdog через 120 секунд удаляет только тестовую nft table,
останавливает тестовый TCP/AWG и парный WG. Перед началом проверяется отсутствие
активной тестовой VPN-цепочки; новый harness также проверяет другие NM WireGuard-сессии.
При штатном завершении сначала удаляется блокировка, затем соединения; проверяются
отсутствие тестовой table, активного VPN/marker и совпадение IPv4/IPv6 rules с baseline.
После подтверждения очистки watchdog отменяется и его временный файл удаляется.

## Результаты и незакрытый вопрос

Первый прогон: AWG был исправен до блокировки, две проверки после неё вернули false
через 21.12 и 42.24 с. Итог — AssertionError, cleanup прошёл. Исходный harness не
различал проверку конечного live-state и последующую healthy, поэтому точная причина
этого отказа не установлена. Переключение не считается успешно принятым в этом прогоне.

В harness добавлены номера этапов, live-state и exit code операций TCP-helper.
Дополнительно исправлена проверка чужих NM WireGuard-сессий на точное значение строки.
Код клиента, тайм-ауты и helper не менялись.

Второй прогон прошёл: две failed health cycles (21.09/42.21 с), TCP healthy через
45.32 с. Live-state: TCP true, AWG false, WG false. UDP-счётчик зафиксировал 1047
отброшенных пакетов (включает VPN/background traffic, не число тестовых запросов).
Unprivileged health, resolved query, явное disconnect/stop policy и очистка прошли.

Третий прогон также прошёл: failed cycles 21.08/42.15 с, восстановление 45.57 с,
TCP true/AWG false/WG false. UDP counter 1154; health от обычного пользователя,
DNS, disconnect/stop policy и cleanup прошли. Итого: один неуточнённый отказ,
затем два последовательных успешных восстановления без изменения продуктового кода.

Первый отказ не исчезает из результатов из-за успешного повтора. Короткие серии
показывают работоспособность механизма, но не дают оценки долговременной надёжности.
[Все результаты попыток](../awg-tcp-recovery-result.json).

## Состояние, следующий шаг, откат

Два успешных backend/policy прогона позволяют перейти к GTK/polkit end-to-end приёмке
экспериментального Linux-клиента: запустить реальный UI, проверить восстановление,
согласованность выбранного профиля/статуса и остановку восстановления при Disconnect,
закрытии приложения и отмене авторизации. На неуспехе health сохранять точный этап
и код ошибки без ключей; первый неуточнённый AssertionError остаётся открытым наблюдением.
Это ещё этап 3; затем интеграция/проверки платформ и подписанный стабильный выпуск.

Стабильный Linux 0.2.7, опубликованный desktop 0.2.8, сервер 0.2.1/Xray 26.3.27
не менялись. Основной WG/AWG launcher не переключён на экспериментальный TCP-код.
Новых установок, push, CI или релиза в этой серии нет. Исправленный TCP-helper остаётся
установленным после предыдущего этапа; backup /var/backups/family-connect/tcp-routing-1789119289/helper.
Откат кода не требовался: все временные сетевые изменения убраны. При необходимости
отката helper сначала подтвердить отсутствие новых правил/marker, затем восстановить
backup как root:root 0755 согласно предыдущему отчёту.

Операторский скрипт и результаты сохранены вне Git в state-client-build/awg-tcp-recovery
(0700/0600), без профилей и ключей. Изменён только harness; py_compile и git diff --check
прошли. Полный Python/GTK-набор не повторялся; прежние 222 passed не являются новой серией.
