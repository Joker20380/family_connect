# Friends: запас на расхождение часов при получении конфигурации

24.09.2026 пользователь сообщил об Android beta50: «не удалось получить список
серверов». У последнего активированного устройства на RU наблюдались8 неиспользованных
NL challenges; подтверждённого запроса configuration для него в момент диагностики
не было. Это согласуется с отказом клиента до отправки proof, но без диагностики
самого проблемного телефона не доказывает единственную причину инцидента.

Воспроизведён отдельный дефект протокола: сервер выдавал expires_at=now+120, клиент
Android/desktop проверял expires_at<=client_now+120. Отставание клиента даже на1с
приводило к invalid_response и общему сообщению об интернете. Новые regression tests
с lag1/20s сначала упали, после исправления прошли.

В Access и ChatAccess срок challenge сокращён до100с (общая CHALLENGE_TTL), что
оставляет20с запаса до неизменённой клиентской границы120с. Серверный срок в DB
также100с; просроченный proof и повторное использование по-прежнему отклоняются.
Большое расхождение часов требует исправления времени на устройстве. Подписи,
привязки identity/WG, revocations и лимит8 outstanding challenges сохранены.

45 tests passed: Friends access/client/chat, включая lag1/20s, отказ при21s lag
и отказ по серверному сроку100с. На RU перед заменой сверены хеши обоих старых
модулей с Git; предыдущий код сохранён локально в закрытом source-backup каталоге.
Заменены только app/control/friends/access.py и chat.py; перезапущен API доступа.
HTTPS probe получил200/TTL100; API/AWG/TCP и chat-sync.timer active.
При откате вернуть оба предыдущих модуля, перезапустить только API и проверить
challenge; rollback вернёт прежнюю чувствительность к часам. DB миграции нет.

Публичный APK на сервере имеет SHA256
`8a1d44eac8cdd45bb9225e930c71377ea5b38428238300803fecc42a60761369`, совпадающий с
локально проверенным package com.familyconnect.app.friends, label family_connect,
FriendsActivity, versionCode50. Проверка по полному HTTPS download на ноутбук
завершилась timeout; хеш проверен у опубликованного файла непосредственно на RU.
На подключённом телефоне есть и friends50, и отдельный pilot50. Одинаковый номер
не означает одинаковый интерфейс; pilot не заменяет пользовательскую сборку.

Версии клиентов не менялись: Android0.1.18-beta50, Linux0.2.10, Windows0.2.13.
После установки исправления и повторной попытки пользователь подтвердил:
«подключился». Пользовательская приёмка этого инцидента закрыта. Не установлено,
менялась ли одновременно настройка времени телефона: отдельно измеренное
расхождение проблемного устройства отсутствует. Полный длительный VPN-тест
этим подтверждением не заменяется.
