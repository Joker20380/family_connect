## Collection and privacy

- The initial pinned RU read selects only consenting, fresh, connected AWG sessions
  on `nl-amsterdam-1` or `nl-amsterdam-2`, using the canonical full device/key binding.
- Read-only, host-pinned SSH samples the selected NL gateway. Its installed transport
  archive must match the existing per-node pin; node state must bind the same full
  device ID and key. Only endpoints with a recent AWG handshake are returned.
- A second pinned RU read obtains current metadata and canonical bindings again.
  Consent epoch, sequence, node and key must still match before the central local
  DB-IP lookup. Revoke, changed binding, wrong node, future/stale time and duplicate
  observations cannot supply a new location.
- IPs and public-key joins remain in process memory/SSH stdin/stdout only, never in
  the exported HMAC2 projection, evidence, application logs or saved snapshots.
  No third-party lookup API, forwarded-header trust or database copies on NL.
- The complete external collection retains a45s deadline within the unchanged50s
  monitor call; optional NL failure does not discard already read OS/consent data.
  Failed final reread cannot import a newly sampled location. Existing independently
  aged, seven-day last-known geography remains unchanged, and revocation clears it.
