# Windows TCP: профиль и broker storage

Дата: 2026-09-11. Продолжение этапа 4 после нативной приёмки TCP-движка.
Пользователь подтвердил порядок Windows → Android → Reticulum.

Добавлены отдельный Ed25519 domain TCP-активации, строгая схема профиля,
привязка к существующему коду Windows-устройства и монотонный sequence.
Неизвестные/повторные поля, чужое устройство, истёкший срок импорта, откат,
подмена той же версии, небезопасный endpoint/REALITY-параметры отвергаются.
Конфигурацию Xray строит клиент; импорт не принимает команды и пути.

Broker `activate-tcp` работает от LocalSystem, выбирает профиль по SID named pipe,
сохраняет исходный подписанный envelope атомарно в `.tcp.dpapi` через DPAPI.
Подпись и параметры проверяются повторно при чтении. Срок действия ограничивает
импорт; принятый профиль остаётся доступным офлайн, серверный отзыв — отдельный механизм.
`tcpReady` в статусе означает наличие файла; не означает подключение или проверку
доступности gateway. `connect` пока работает только с WG, GUI ещё не импортирует TCP.

Добавлен offline issuer `scripts/activate_windows_tcp.py`. Это операторский инструмент
для уже зарегистрированного TCP UUID; он не меняет gateway. Приватный результат
не перезаписывается и не публикуется. В Git только синтетическая fixture.
[Runbook](../windows-tcp-profile.ru.md).

Локально: 300 Python tests passed, включая 19 новых. C# profile tests прошли:
29 отрицательных случаев, round-trip, конфигурация и общая Python fixture.

Первый phase0 остановился при сборке control test stage: в контейнере отсутствовал
общий `clients/desktop/profile_config.py`. Диагностика сохранена в CI artifacts;
исправлено в `b46f1f3` добавлением парсера только в test stage, runtime image не менялся.
Первый Windows broker integration test остановился с InvalidOperationException;
последующая точная диагностика и результат отмечены ниже.

## Остаток плана

Windows ещё не завершён. Следующие обязательные части:

1. Владение Xray процессом службой, запуск без открытого профиля на диске,
   остановка и cleanup при сбое/перезапуске брокера.
2. Применение/откат собственных IPv4/IPv6 маршрутов и DNS, обход gateway без routing loop,
   сохранение настроек других адаптеров/пользователей.
3. Импорт и выбор TCP в GUI, ошибки/отмена, мониторинг и восстановление; Windows AWG.
4. Windows runtime/platform gates, неизменяемая новая версия и подписанный каталог.
5. Затем интеграция транспортов Android и его платформенная приёмка.
6. Затем этап 5: реальная Reticulum-доставка подписанной конфигурации, проверка,
   применение, ACK/откат, защита от повторов и доступный служебный вход.

Google Play и кнопка Android updater не являются условием начала Reticulum.
Второй независимый VPS требуется для этапа 6 со сменой заблокированного gateway;
его отсутствие не блокирует реализацию обмена Reticulum.
Пользовательские сетевые/нагрузочные тесты остаются отложенными.

Нового релиза/установки/развёртывания нет. Desktop published 0.2.9, Linux installed
0.2.7, Windows last reported 0.2.7; server0.2.1, TCP component/Setup0.1.0.
CI installer по-прежнему носит исходную версию0.2.9 и не должен подменять публичный
неизменяемый release0.2.9. Перед публикацией требуется новая версия и exact-source CI.
Откат на устройствах не нужен; убрать эту интеграцию из будущего installer при отмене.
