## TCP-пилот

Прежний scripts/check_tcp_matched.py, 24 раунда: одинаковый numeric HTTPS endpoint
напрямую/TUN/SOCKS, UDP DNS напрямую/TUN. HTTPS connect-timeout 3 с, max-time 5 с;
DNS 3 с, без повторов. Docker bridge namespace, без изменения маршрутов ноутбука.
Исправленный routing helper из 6d7f569, прежний Xray 26.3.27 и тот же сервер.

**120/120 проб прошли, exit 0, failures пустой.** Каждая категория 24/24:
HTTPS direct, TUN, SOCKS; DNS direct, TUN. Очистка правил прошла, Xray завершён,
отсутствие интерфейса TUN подтверждено скриптом; одноразовый контейнер удалён.
Серия около 63 секунд, один HTTPS endpoint, новые короткие соединения и ограниченная
нагрузка. Это не доказательство устойчивости всех приложений или работы часами.

## Состояние и следующий шаг

Смена сети сопровождалась исчезновением ошибок в этой ограниченной TCP-серии
без изменений кода или тайм-аутов. Это подтверждает значимость качества локальной
сети для прежней диагностики, но не доказывает единственную причину всех старых сбоев.

Следующий шаг: сохранить backup установленного старого helper, установить исправленную
версию из экспериментальной ветки и выполнить короткий host smoke с проверкой
маршрутов, DNS, HTTPS и очистки. Затем проверить established AWG → TCP recovery.
Оставаться на новой сети для сопоставимости; не начинать сразу длительный host-wide тест.
Смена Wi-Fi и изолированные проверки завершены, физическое переподключение больше
не является ожидающим действием пользователя.
