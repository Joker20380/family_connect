# Уточнение AWG3.1 после исправления выдачи конфигурации

24.09 пользователь сообщил: TCP REALITY заработал на Wi-Fi, прежняя попытка AWG3.1
не удалась. Затем уточнил: AWG проверяли до исправления Friends challenge,
после исправления не повторяли. Поэтому отдельный отказ AWG/UDP в этой сети пока
не подтверждён. Сообщение об ошибке списка серверов относится к этапу получения
конфигурации, а не само по себе к handshake транспорта.

Read-only диагностика NL: Friends AWG/TCP active, NRestarts0; у AWG14 runtime peers,
4 handshake за5 минут,10 peers с handshake когда-либо. У последней разрешённой
регистрации в API найден постоянный и runtime peer на NL, handshake и двусторонние
счётчики трафика. Привязка этой записи именно к обсуждаемому телефону не подтверждена;
она не выдаётся за пользовательскую приёмку. На RU peer этой записи отсутствует,
что само по себе не ошибка: регистрация производится для выбранного gateway.

Пользователю предложено повторить Нидерланды→AWG3.1 на той же Wi-Fi-сети после
исправления. Результат ожидается. При отказе сопоставить время попытки и устройство,
разделить API/profile/native startup/UDP handshake/routing-health. Мобильная сеть
ещё не проверялась; вывод о блокировке UDP оператором не делался.

AWG3.1 есть в обычном Friends beta50. Этап5.3а относится к managed конфигурациям,
журналу/службе и парку серверов; это не утверждение об отсутствии AWG в пилоте.
Runtime/code/configs не менялись, тесты не запускались. Android beta50/code50,
Linux0.2.10, Windows0.2.13 прежние. Предыдущий clock fix сохранён.
