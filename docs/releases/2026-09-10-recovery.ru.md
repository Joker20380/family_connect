# Восстановление работающего VPN — 10.09.2026

Продолжение AWG-пилота, базовый локальный commit `2e6e1d4`.
Пилотный Linux-клиент теперь контролирует соединения, которые пользователь включил
в этом экземпляре приложения, и восстанавливает их после обрыва. Уже работающий
чужой/ранее включённый туннель при запуске приложения автоматически не присваивается.
Закрытие клиента останавливает мониторинг, сохраняя включённый VPN; об этом сказано
в подтверждении закрытия. [Машинный результат](../linux-recovery-result.json).

## Поведение

Проверка раз в 15 секунд, последовательно через Cloudflare HTTPS trace и ipify HTTPS.
Достаточно успешного ответа одного сервиса с ожидаемым внешним IP. Оба запроса явно
привязаны к VPN-интерфейсу; обычный маршрут, proxy environment и пользовательский curlrc
не используются для подтверждения. Системный curl вызывается по абсолютному пути.
Формат второго сервиса: [официальная документация ipify](https://www.ipify.org/).
На одном сервере ожидаемый IPv4 egress равен endpoint; другие схемы NAT/multi-gateway
потребуют отдельной модели ожидаемого выхода.

После двух подряд неудачных циклов проверки клиент восстанавливает подключение.
Если оборвался работающий WG, он отключает его и сразу пробует парный AWG.
При отказе AWG он пробует исходный WG с имеющимся connection-time fallback.
Не больше трёх попыток, паузы 15/30/60 секунд; короткий успех не обнуляет бюджет.
Счётчик попыток сбрасывается после 60 секунд наблюдаемой стабильности.

Проверочный поток не меняет маршруты. Решение применяется в основном потоке GUI,
а сетевое действие выполняется в очереди операций после сверки выбранного профиля
и версии состояния UI. Явное отключение, смена выбора, закрытие и отмена Polkit
останавливают намерение восстанавливать. Запоздалый результат health-check не может
снова включить VPN после отключения. Операции подключения/восстановления сериализованы;
во время выполняющегося системного действия используются прежние ограничения busy UI.
Системное подтверждение администратора для AWG сохраняется; отсутствие беспарольного
broker означает, что некоторые восстановления могут потребовать действия пользователя.

## Проверки и измерение

- Полный Python-набор: **199 passed**, включая **55 desktop tests**.
- GTK: прежние polling/confirmation/state regressions, **24 layout cases**, новые
  сценарии порога восстановления, Disconnect, устаревшего ответа, смены выбора,
  закрытия и отмены авторизации. Добавлены в клиентский CI workflow.
- Реальный ноутбук: сначала успешно установлено WG-соединение, затем отдельной nft
  table заблокирован только UDP/51820 к `185.251.89.19`. Монитор с производственным
  интервалом 15 секунд получил два отрицательных цикла и восстановил VPN через AWG
  за **44.05 с**. Проверка здоровья выполнена также от обычного
  пользователя. Тестовая таблица и туннели удалены; явное отключение остановило policy.
- Root harness использовал уже выданное операторское разрешение. В измерение не
  входит время ввода пароля Polkit. Это имитация блокировки endpoint на ноутбуке,
  а не проверка российских DPI-систем или всех типов сетевых отказов.
- Воспроизводимый операторский harness: `scripts/check_linux_recovery_live.py --help`.
  Он требует root, существующего парного профиля и отсутствия активного тестируемого
  VPN, сохраняет helper backup, устанавливает reviewed helper и всегда убирает свои
  firewall rules/туннели при обычном завершении или исключении. SIGKILL/потеря питания
  не покрываются finally; в таком случае требуется операторская очистка его nft table.

## Установка, версии и откат

Обновлён установленный root-helper; предыдущая копия:
`/usr/local/lib/family-connect-awg-before-recovery-1789075817`. Новая копия дополнительно содержит root-owned backend.py
с общими health-checks. Ключи, профили и привязка WG/AWG сохранены.
Ярлык **Family Connect — AWG pilot** использует обновлённый исходный код; уже открытый
пилот нужно перезапустить, чтобы загрузить новый монитор. Стабильный Linux 0.2.7,
опубликованный desktop 0.2.8 и его signed catalog не менялись. GitHub CI этих новых
локальных изменений пока не запускался, кроссплатформенный релиз не публиковался.

Серверные образы/конфигурация в этом этапе не менялись: WG и product 0.2.1,
отдельный AWG `family-connect-amneziawg:2-pilot1` на UDP/51821. Предыдущий серверный
отчёт и инструкции отзыва AWG остаются действующими.

Откат: закрыть пилот, отключить его туннель, восстановить helper из указанной копии
с правами root и использовать клиент из базового commit `2e6e1d4` либо установленный
стабильный Linux 0.2.7. Восстановление БД или серверных ключей не требуется.
