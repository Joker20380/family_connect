# Приглашения: 50 прямых + 500 реферальных — 2026-09-19

Реализовано и развёрнуто по запросу пользователя. Это отдельные бюджеты:
50 подготовленных прямых кодов и 500 последующих выдач по QR участников.
Android остаётся на исходной версии 0.1.7-beta08/code8; новый APK не собирался,
не устанавливался и не публиковался. Последний опубликованный desktop v0.2.9
не содержит этих Android-изменений. Текущий git HEAD 3f6f662 не описывает dirty
deployment: точные SHA256 публичных исходников записаны в
[машинном отчёте](2026-09-19-referrals.json).

## Пользовательский путь

1. Один из 50 прямых кодов активирует одно устройство.
2. В исходниках FriendsActivity доступен экран «Пригласить друга»:
   активированная device identity подписывает одноразовый challenge `refer`.
3. API возвращает постоянную персональную ссылку; Android кодирует её в QR.
4. Друг открывает HTTPS-страницу и явно нажимает «Получить приглашение».
   Простой просмотр ссылки ничего не расходует.
5. Сервер атомарно создаёт новый одноразовый код из общего пула 500.
   После активации этот участник может показывать уже свой QR.

Ссылки имеют вид `https://185.251.89.19:8443/invite/#<token>`; fragment не попадает
в HTTP access log. Страница использует no-store, no-referrer и CSP с хешами
точных inline script/style. Настоящих кодов/токенов в этом документе нет.
Download пока не обещается: страница просит сохранить код до выпуска сборки.

## Ограничения выдачи

- Общий бюджет 500 сохраняется в SQLite, не сбрасывается при рестарте.
  Считаются выданные, а не активированные коды; обычный отзыв не возвращает место.
- 20 новых кодов на приглашающего за скользящие 24 часа.
- Повторный request ID возвращает прежний код, включая его состояние activated.
  Браузер хранит случайный ID в localStorage до сетевого запроса. Очистка данных
  или другой браузер создаёт новый запрос; это не доказательство уникального человека.
- Отзыв device/invite приглашающего блокирует новые выдачи. Уже выданные детям
  приглашения независимы и не отзываются каскадно.
- QR можно переслать. Это ограниченный реферальный пилот, без проверки личности
  и без гарантии защиты от организованного расходования пула.

Транзакции `BEGIN IMMEDIATE` обеспечивают общий лимит при гонках. В DB находятся
хеши кодов, referral tokens и request IDs. Campaign HMAC key лежит только на API
хосте в `friends-access/referral.key` (0600). Его нельзя менять или терять:
восстановление ссылки/кода зависит от этого ключа. Backup должен включать его,
`access.db` и приватный `direct-50.json`, вне Git/CI. Исходные 10 кодов сохранены.
Все 50 лежат локально в игнорируемом `state-enroll/friends-pilot/FamilyConnect-invitations-50.txt`
с правами 0600; не включать файл в публичные артефакты.

## Откат и повторная установка

Откат API: остановить `family-connect-friends-access`, восстановить прежние
`app/control/friends/access.py`, `app/control/friends/chat.py`, `access-api.py`
из `friends-access/backups/20260919-144035/`. Восстановить оба nginx файла оттуда
в `state-product-https/config`, проверить `nginx -t`, запустить API и выполнить
HUP ingress. Это закрывает реферальные маршруты, сохраняя старую активацию.
Сохранить новую DB, key, direct-50.json и таблицы: не откатывать рабочую DB
целиком, иначе будут потеряны выданные приглашения и привязки устройств.

Повышенный membership cap можно оставить при откате API. Возвращать два node
файла из `mailbox-pilot/backups/20260919-144035/` и рестартовать mailbox можно
только после проверки, что dynamic snapshot содержит не более 98 ключей.
Иначе прежняя версия откажется принимать весь snapshot.

`install-access.py` предназначен для первой установки, не для повторного запуска
на рабочем узле. Перед ним нужны полный `app/control/friends` (включая referrals,
chat_sync), admission/device dependencies и `invite/index.html` в service root.
Он создаёт campaign key только при отсутствии referral tables и никогда не
пересоздаёт ключ для существующей кампании. Для обновления сохранить текущие
ключ/DB, скопировать публичные исходники, выполнить additive initialize,
обновить nginx маршруты и CSP из точного HTML, проверить nginx и рестарт API.

## Что остаётся

APK/runtime и сканирование физической камерой после снятия пользовательской паузы;
проверки на двух телефонах, rotation, lifecycle, сеть без/с VPN, релизные gates.
Ещё нужны принятый распространяемый установщик, обновлённый путь скачивания,
нагрузочная проверка и продуктовое оформление GitHub после мессенджера.
Подготовка 550 приглашений не объявляет приложение production-ready.
