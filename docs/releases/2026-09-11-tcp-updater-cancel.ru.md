# Ручная отмена авторизации TCP updater — 11.09.2026

Ближайший пункт плана закрыт: настоящий desktop GTK → pkexec для установленного
/usr/local/lib/family-connect-tcp-updater/broker install вернул **126** после отмены.
Приложение показало «Установка TCP отменена», сняло busy, сохранило выбранный элемент
и состояние «отключено». За 18 секунд наблюдения повторных вызовов pkexec не было.
Хеши установленных xray/helper/backend/profile_config и список component backups
до/после идентичны. TCP был inactive по systemctl перед запуском проверки.

Использован настоящий GTK smoke-window с синтетическим выбранным профилем и
состоянием «отключено». Кнопка и подтверждение вызваны через реальные GTK signals;
отмена сделана в системной авторизации. Production backend/установленный root-owned
broker использовались без подмены результата или AuthorizationError. Обёртка только
записала настоящий returncode и ограничила ожидание команды 180 секундами.
Policy/agent/cache авторизации не менялись и не отзывались. При успешной авторизации
этот тест не засчитал бы отмену. При 127 (недоступная авторизация) — также не засчитал бы.

Это проверка отмены отдельной установки; не повторная проверка сетевого recovery,
не проверка реального профиля и не приёмка чистой VM. Тестовое окно приложения
закрыто, исходный код не менялся; широкие регрессии повторно не запускались.
Предыдущие 260 тестов и platform CI ревизии 92308a4 остаются последней проверкой кода.
