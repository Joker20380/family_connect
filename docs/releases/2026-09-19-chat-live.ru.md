## Разрешения и отзыв

ChatAccess.snapshot увеличивает сохранённый sequence в одной SQLite-транзакции и
выдаёт активные public keys с expires_at=now+100с. Каждые20с systemd timer повторяет
публикацию. API register синхронно публикует snapshot перед ответом active.
Публикация сериализована неблокирующим flock: занятость даёт временный отказ,
вместо неопределённого ожидания. SSH connect5с, subprocess10с, timer service15с.

Отдельный SSH key остаётся только на API-host в friends-access/chat-sync-key.
На node разрешён исключительно forced command accept_membership.py, from185.251.89.19,
restrict; host key получен через уже проверенную SSH-сессию и отдельно закреплён.
Release signing key не используется. Membership/ключи не выводятся в журналы/Git.

Root helper проверяет срок/размер/sequence, атомарно записывает root:fc-mailbox0640
members.json с fsync и подтверждает bootstrap/sequence/expiry при active service.
Старый sequence отвергается под flock. Daemon читает lease на каждом запросе:
повреждённый/просроченный файл не даёт dynamic access, в том числе на старом link.
Две прежние диагностические identity остаются статическими. Dynamic список до98
ключей; рабочая цель50 помещается вместе с ними. Spool quotas не увеличены.

Удалённый отзыв действует при следующем успешном snapshot; при нарушенной связи
старое разрешение истекает максимум через100с от выдачи (с учётом времени часов
хостов). Уже начатый разрешённый запрос может завершиться: это не откат ciphertext
и не secure erase ранее полученных сообщений.

## Android source

FriendsAccessAndroid принимает active только с проверенными device/chat/expiry/
sequence и bootstrap из аутентифицированного HTTPS-ответа. ChatActivity включает
carrier после этого ответа, запоминает факт регистрации и при новом открытии
получает свежую регистрацию/bootstrap. Ошибка сети сохраняет локальную историю.

NetworkCallback сообщает о доступности underlying non-VPN networks. OnStop закрывает
owner/worker по существующей FIFO очереди; поздние UI результаты отсекаются.
Локальный state tick2с обновляет UI после exchange; это не опрос удалённого узла.
Получение запускается при foreground/online событиях, отправке и явном «Обновить».
Постоянные фоновые уведомления/Doze/push не реализованы. Android lifecycle/network
поведение ещё требует runtime acceptance; новые native источники не установлены.
