# Ревью и интеграция TCP в main — 11.09.2026

**Исходники TCP-пилота интегрированы в основную ветку вместе с WG/AWG.**
Это интеграция кода, не выпуск новой стабильной версии и не установка системных компонентов.
Экспериментальная ветка сохранена. Правки ревью: ca2a63a.
Перенесён текущий non-doc diff (21 файл); актуальные документы main сохранены отдельно.

## Результаты ревью и изменения

Проверены строгая схема профиля и запрет произвольных hooks/config, root-owned файлы,
маршрутный ownership marker/точная очистка, резервирование приоритетов, остановка
цепочки при ошибке cleanup/отмене авторизации и поведение без TCP-профилей.
Это целевое ревью, не независимый аудит безопасности.

1. install-tcp.sh теперь отказывает до первого изменения файлов, если существует
   active marker либо есть active/activating/deactivating TCP unit. Ошибка чтения
   состояния systemd также прекращает установку. Это защищает от замены helper
   во время его работы; установку после остановки всё равно выполнять с backup.
2. Проверка WG в цепочке с AWG использует endpoint парного AWG, а не endpoint TCP,
   который может отличаться. Добавлен regression с разными адресами gateway.
   Для пары WG+TCP без AWG пока сохраняется односерверное предположение пилота;
   полноценная разносерверная provisioning/egress модель ещё не реализована.
3. Добавлен regression отсутствия TCP-профилей: управление WG/AWG передаётся прежнему
   backend. Существующие tests отмены/ошибки очистки и приоритетов транспорта сохранены.

Интеграция включает backend factory LinuxTCP, строгий parse_tcp/config builder,
root-helper/systemd/installer, отдельный compose/Dockerfile/лицензию Xray,
TCP workflow и воспроизводимые операторские diagnostics. Android/Windows реализация
новых транспортов этим diff не добавлена. История экспериментальной ветки не удалялась.

## Установка и ограничения выпуска

Стабильный ярлык запускает ~/.local/share/family-connect/current/app.py — он не менялся.
Пилотный family-connect-awg-pilot.desktop запускает clients/desktop/app.py из main;
его следующий запуск уже использует объединённую WG/AWG/TCP-цепочку. Сам ярлык не правился.
Linux 0.2.7 установлен; desktop 0.2.8 опубликован; сервер 0.2.1/Xray 26.3.27 прежние.
Установленный TCP-helper с routing fix не заменялся в этой серии. System dependencies
helper/backend требуют отдельной установки при последующем rollout, а не обновились
автоматически вместе с Git. Нет host VPN-теста, серверного изменения или новых ключей.

Шестифайловый updater-архив не устанавливает Xray/root helper/systemd автоматически.
На чистой машине для TCP ещё нужен отдельный install-tcp.sh и бинарник Xray. Полноценный
продуктовый rollout требует решения этой зависимости, подтверждённой сборки/установки,
native Windows/Android поддержки, актуального CI и нового неизменяемого релиза с
офлайн-подписанным каталогом. Нельзя публиковать изменённые бинарники как прежнюю 0.2.8.

Первый неуточнённый AssertionError backend recovery остаётся открытым наблюдением;
две успешные backend-серии, GTK recovery и ручная отмена авторизации не скрывают его.
В этой серии новая телеметрия production health не добавлялась.

## Следующий шаг и откат

Следующий этап: воспроизводимая сборка/установка TCP-компонентов для чистого Linux
с сохранением updater-совместимости, затем native Windows/Android интеграция и
platform CI. До этого не объявлять единый стабильный клиент готовым. Сетевую доставку
Reticulum/второй VPS реализовать по ROADMAP; на одном IP отказоустойчивость не полная.

Интеграция сохранена локальным коммитом main; push/GitHub CI/release пока не выполнялись.
Для отмены исходников — revert коммита интеграции, сохраняя последующие пользовательские
изменения. Это не системный rollback: приложение/сервер не устанавливались. Backup
установленного helper и порядок его отката остаются в host-smoke отчёте.
