## Поведение

`messenger.local.LocalChat` разделяет первую регистрацию (`create=True`) и
возобновление (`create=False`). Повторная регистрация поверх каталога отклоняется.
При resume отсутствие каталога, lock-файла, базы или identity, неверный ключ и
повреждение зашифрованных записей дают `store_unavailable`. Ошибка не создаёт
новую identity и не заменяет прежние данные. Ошибки содержат фиксированные коды.

Контакт добавляется по полному публичному ключу64 bytes с явным совпадением
SHA256 fingerprint. UI ещё должен обеспечить независимую проверку отпечатка;
копирование fingerprint из того же недоверенного источника не проверяет человека.
Свой ключ как контакт отклоняется. Неизвестному контакту нельзя поставить письмо
в очередь; текст ограничен4096 UTF-8 bytes, некорректный Unicode отклоняется.

Локальные операции и закрытие сериализуются. Сохранение возвращает ID после
транзакции. История выдаёт только id/peer/text/timestamp/outgoing/status,
до100 сообщений на страницу, total/next_offset. Ключи, packed plaintext,
relay ciphertext и attempt tokens остаются внутри ядра. Старый sending после
перезапуска отображается queued; повтор использует прежние подписанные байты.
Relay acceptance остаётся отдельным статусом, не подтверждением прочтения.

Исправлено изменение порядка сообщений при обновлении статуса: SQL UPSERT
обновляет строку без удаления/повторной вставки и сохраняет rowid. Формат
зашифрованной базы остаётся1; AES-GCM/AAD и wire format не менялись.
Старый Store open-or-create сохранён для существующего prototype API.
Удаление отдельных записей и rollback всей базы по-прежнему не обнаруживаются
надёжно; эта работа не вводит отдельный журнал защиты от отката.

## Следующее изменение и rollout/rollback

Следующий подпункт: подключить LocalChat к ChatKeyVault через Android bridge,
проверить упаковку LXMF и AES-GCM без изменения VPN identity, обеспечить одного
владельца Python/RNS и добавить runtime tests открытия/повреждения/process death.
Затем carrier/outbox/подтверждения сохранения, Android UI, два телефона и условия
фоновой доставки. История plaintext неизбежно доступна процессу работающего
клиента; Python API не обещает гарантированное стирание копий ключей из памяти.

Это изменение исходников, без rollout на телефон/сервер. Перед выпуском нужны
platform CI, проверка скачанных артефактов, новая неизменяемая версия при изменении
опубликованных бинарников, offline signing и физическая приёмка.
Не включать Python API в продукт под видом готового чата до этих проверок.

Откат текущего этапа: убрать вызовы LocalChat, вернуть прежнюю реализацию
messenger/chat.py и store.py из базового checkpoint; база format1 совместима,
удалять историю/ключи/профили не нужно. Для ещё не развёрнутого bridge нет
серверных действий отката. Сервисы VPN, mailbox, инвайты и signing key не менялись.
