# TCP-комплект: чистая установка с настоящим systemd — 11.09.2026

Проверка выявила недостающую зависимость: helper вызывает sysctl, а чистый Debian slim
не содержит procps. Исходный установщик принимал такую систему. Исправлены preflight
обоих Linux TCP установщиков и список зависимостей комплекта; новый регрессионный тест
проверяет отказ без sysctl до открытия файлов состояния. Runtime helper/Xray не менялись.

## Среда и результат

Debian 12 amd64 Docker, настоящий /sbin/init (systemd PID 1), systemd-resolved 252.39,
Python 3.11, curl 7.88.1. Исходный тестовый образ 7c2062dbf708 без procps; в новом чистом
контейнере исправленный установщик отказал с `Missing dependency: sysctl` до создания
каталогов компонентов/backup. Затем установлен procps 2:4.0.2-3 и выполнена свежая установка.
Dockerfile для последующих повторов уже включает procps. Использованы private network/cgroup,
privileged mode, tmpfs /run,/tmp. Ядро общее с ноутбуком; это не VM/hardware certification.

- Реальные systemd и resolved активны, без заглушек; служба запускается production helper.
- DNS: запрос через TUN/resolvectl, обычный getent через resolved stub; HTTPS 3/3 после
  установки и 3/3 после переустановки, egress соответствует VPN gateway.
- Установка при активном туннеле отклонена без нового backup.
- Штатная остановка убирает TUN, ownership marker, таблицу 64630 и точно возвращает
  полный IPv4/IPv6 rule baseline.
- Повторная установка тех же компонентов сохраняет содержимое профиля и mode 0600;
  повторный запуск проходит. Обновление на иную версию здесь не проверялось.
- SIGKILL основного процесса службы: настоящий ExecStopPost выполняет очистку;
  TUN/marker/table отсутствуют, rule baseline восстановлен. Финальная очистка прошла.
- До этой свежей установки те же проверки прошли в первом контейнере после добавления
  procps и замены исходного комплекта исправленным. Оба контейнера остановлены/удалены.
- Полный Python suite: **230 passed**, два прежних deprecation warnings.
  Файловый тест установки/tamper/upgrade/rollback повторно прошёл; только он использует
  заглушки systemd/resolved/pkexec/sysctl. Живой тест не подменяет эти команды.

[Машиночитаемый результат](../tcp-systemd-result.json).
Операторский сценарий: scripts/check_tcp_systemd.py; профиль передаётся только read-only
и не попадает в Git/CI/вывод. Сценарий намеренно привязан к разрешённому пилотному gateway.

Новая сборка engine не выполнялась. Комплект заменяет только локальный неподписанный
pilot artifact; опубликованные 0.2.8/tag/catalog не изменялись.
Установщик сохраняет backup/restore.json; порядок установки и ручного восстановления:
[runbook](../linux-tcp-install.ru.md). На ноутбук исправленный комплект не устанавливался;
стабильный Linux 0.2.7, сервер 0.2.1 и установленный routing-helper остаются прежними.
Откат теста — удаление одноразовых контейнеров; это выполнено.

## Дальше

Аутентифицированная доставка отдельного компонента, native Windows/Android, platform CI
и новый подписанный выпуск. Перед широким rollout нужна чистая VM/оборудование и
интерактивная авторизация на такой системе. Контейнер не проверяет polkit UI,
самостоятельное ядро, длительную устойчивость или потерю IP gateway. Reticulum delivery
и второй независимый gateway остаются отдельными этапами. Старое неуточнённое падение
health/recovery не объявлено исправленным этой проверкой.
