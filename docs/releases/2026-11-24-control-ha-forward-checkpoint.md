## Wire contract and independent trust

- Canonical UTF-8 JSON from `request_for`, exact fields and a16KiB bound; duplicate,
  noncanonical, unknown, missing, wrong-type and unbounded fields refuse verification.
- Purpose `family-connect/current-state-checkpoint/v1/isolated-qualification-only`;
  only action `QUALIFY_CURRENT_STATE_OFFLINE` is valid. Capture, import, historical
  approval and host-resume actions cannot be substituted even with a valid signature.
- Authorization is an Ed25519 signature over `DOMAIN + request`, where `DOMAIN` is
  the UTF-8 purpose followed by `\x00authorization\x00`. No signature is generated by
  the implementation. Tests generate temporary keys; release/issuer/production signing
  keys are not used as authorization signers. A future trusted authority registry and
  actual owner signing workflow remain to be designed and reviewed, not installed here.
- Verifier requires a separately trusted public key **and** an independently retained
  SHA256 of the approved canonical request, not values obtained from that request.
  The request pins recovery/custody identifiers, ciphertext hashes, canonical snapshot,
  complete history manifest/inventory, anchor, current issuer public-key hash, all three
  runtime/config hashes and both exact publication byte hashes. No raw secret is placed
  in the public request. Keep authorization/checkpoint metadata in private custody too.
- Checkpoint ID must match the recovery capsule; sequence must exceed an external
  retained minimum. Current CRL must meet a separately supplied retained minimum.
  Capture time cannot be in the future; authorization expires exclusively at
  `expires_at`, at most3600seconds after claimed capture. Verifier is read-only and
  does **not** persist/advance floors or consume a permit. Rechecking the same request
  before externally advancing its floor is intentionally idempotent, not single-use
  production authorization. Durable replay-floor custody remains a prerequisite.

Independent pins/floors cannot be regenerated from the supplied bundle after losing
their custody. A new signed higher sequence is not permission to lower a known CRL
floor. The signed request binds the approved issuer; it is not a key-rotation permit.
Caller-supplied source hashes are bound, not remotely attested. A declared capture
timestamp and stable file bytes are not a qualified cross-store writer barrier.

## What validation does and does not establish

Current capsule passes the existing application-schema, signed authority/CRL, external
role, receiver and bounded-maintenance checks; pending bounded maintenance is refused.
The first publication must exactly equal the current issuer directory. Both publication
byte strings are pinned; second-node publication **semantics are not yet qualified**
by this contract. Known synthetic adapter schemas are not the installed fleet schema.

Full unequal legacy journals remain byte-for-byte opaque custody, including unknown
or pending historical archive content. Current coordinator must report COMMITTED,
with no owner marker; nodes must have only settled root entries and CLEANED receipts
for that operation. Observed pending/unknown current markers refuse qualification.
These are bounded observations, not live writer discovery, lock ownership or liveness.
No historical gate is re-signed, interpreted as fresh consent or used for replay.

Return type `QualifiedCheckpoint` is separate from old import inputs, with no direct
`snapshot` attribute. Its result is `FORWARD_CHECKPOINT_OFFLINE_QUALIFIED`, never full
DR/cutover acceptance. Activation stays FORBIDDEN; import and host resume stay
NOT_AUTHORIZED. Inner laboratory inputs remain available for explicit isolated tests;
this wrapper is a protocol boundary, not a sandbox against arbitrary Python callers.
