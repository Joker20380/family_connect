# Восстановление доступа у других проектов — 24.09.2026

Сравнение публичной документации, не полевой тест доступности в России и не аудит
закрытых серверных систем. Psiphon и Tor — технические ориентиры, а не прямые аналоги
платного VPN. Источники проверены24.09.2026.

## Подтверждённые механизмы

- **Proton VPN:** Alternative routing для доступа к сервису через сторонние сети;
  Smart Protocol переключает протоколы/порты, Stealth маскирует туннель. Нельзя
  трактовать alternative routing как перенос всего VPN-трафика через AWS.
  [Обзор](https://protonvpn.com/vpn/censorship),
  [проблемы входа и соединения](https://protonvpn.com/support/windows-vpn-issues).
- **Mullvad:** в Android служебный API имеет Direct, Mullvad Bridges и Encrypted
  DNS proxy. Для VPN отдельно предусмотрены автоматический выбор обхода, Shadowsocks,
  QUIC, LWO и UDP-over-TCP. Поддержка при необходимости может предоставить override
  входного IP. Набор функций других платформ может отличаться.
  [Официальная инструкция](https://mullvad.net/en/help/using-mullvad-vpn-on-android).
- **Amnezia:** перезагрузка конфигурации API получает актуальные параметры сервера;
  этот способ описан и для iOS в России. Инструкция не раскрывает внутреннее
  распределение адресов и не доказывает автоматическую смену IP при любой блокировке.
  [API](https://docs.amnezia.org/ru/documentation/instructions/reset-api-config/),
  [iOS](https://docs.amnezia.org/ru/documentation/instructions/amnezia-on-ios-in-russia/).
- **Psiphon:** встроенные, получаемые при подключении и внешние списки серверов;
  внешние списки проверяются закреплёнными публичными ключами. Выдача разделена,
  некоторые списки OSL зашифрованы и доступны при наличии необходимых ключей.
  Клиент пробует несколько серверов/методов одновременно и запоминает успешные.
  [Техническое описание](https://github.com/Psiphon-Labs/psiphon-tunnel-core/blob/master/README.md).
- **Tor:** bridges не включены в публичный каталог, выдаются отдельными способами.
  Это затрудняет сбор адресов, но адрес известен получившему его клиенту.
  [Bridges](https://support.torproject.org/relays/getting-started/what-is-a-bridge/),
  [получение](https://support.torproject.org/tor-browser/circumvention/getting-bridges/).

## Выводы для Family Connect

Инженерный вывод: стоит сочетать независимую доставку конфигурации, проверку подписи,
разнообразие транспортов и ограничение масштаба раскрытия адресов. Пользователь
может узнать свой первый IP-hop. Разделение выдачи усложняет сбор всего парка через
одну учётную запись, но не исключает множество аккаунтов и наблюдение за сетью.
Это модель угроз, не утверждение о конкретных действиях регулятора.

Reticulum обеспечивает постоянную идентичность и доставку по доступной сети, но
не заменяет bootstrap после потери всех путей. В изученных источниках такая роль
Reticulum не описана; это не доказательство его отсутствия у всех игроков рынка.

Для5.2/6 остаются проектными требованиями независимые ingress, адресная выдача после
proof/проверки доступа, ограниченный резерв назначений, подпись/replay защита,
pull/ACK и отсутствие общего VPN-каталога в публичных announces. Сегментация и
multi-ingress ещё не внедрены. Основа требований —
[проект восстановления](../reticulum-recovery-design.ru.md).

Конкурентное преимущество проверять по доле восстановления, P50/P95 времени,
ручным действиям и стоимости резерва в российских домашних/мобильных сетях.
Число протоколов и Reticulum сами по себе преимущества не доказывают.
Проверять отдельно отказ прежних VPN/служебных IP при доступном независимом пути
и полную потерю путей, требующую внешнего bootstrap.
