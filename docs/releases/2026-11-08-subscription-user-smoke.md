## Подготовленный способ подтверждения

После подключения свободного от параллельного управления телефона сначала прочитать
его фактический package/version и исходные настройки, без установки другой сборки.
Далее только обычный UI:

1. Отключить VPN, подтвердить отсутствие другого VPN, открыть подписку/Refresh.
   Свежие время/state/identity в UI сопоставить с новым consumed subscription challenge
   и успешным HTTP-запросом в том же узком серверном интервале; приватный key/proof
   не извлекать. Наличие challenge без успешного ответа недостаточно.
2. Выбрать RU/AWG без Auto; выполнить небольшой HTTPS-запрос **на телефоне**.
   Сопоставить успешный ответ/egress RU, текущий клиентский transport/node и серверное
   наблюдение соответствующего binding/трафика по времени. Запрос с компьютера,
   VPN-значок или один handshake не являются доказательством пользовательского пути.
3. Отдельно подключить RU/TCP и повторить небольшой HTTPS с такой же корреляцией;
   отсутствие переключения на AWG/MESH обязательно. Вернуть исходный узел, режим
   и состояние VPN, проверить результат восстановления.

При неоднозначном маршруте не ставить PASS. Серверные чтения только read-only;
никаких paid-событий, fault injection, изменения часов или перезапуска production.
Один необходимый шаг владельца: подключить по USB доступный для этой проверки телефон,
разблокировать/разрешить USB debugging и подтвердить, что параллельная задача им не управляет.

## Документация и оставшиеся ограничения

[Каноническая инструкция](../operators/subscriptions.ru.md) исправлена: AWG/TCP установлен
на RU/Amsterdam1/Amsterdam2, current оператора работает. Сохранены finite paid leases,
noncohort при обычной потере центра, локальный fail-closed, TCP reconnect collateral,
MESH cert/CRL и получение новых событий только при открытии подписки/Refresh.
Практические activate/grace/expire/revoke, exact replay и terminal/cohort правила не меняются.
Diff ограничен инструкцией, текущими STATUS/PLAN и этим отчётом; runtime/Android payload
не изменены. Результаты docs gates, CI и merge будут в PR этой задачи; docs merge не
закрывает BLOCKED пользовательского smoke. Исторические отчёты/receipts сохранены.

**NOT_RUN:** реальная платная операция; физический paid/event-сценарий; production E2E
Amsterdam1/2, mixed-network, MESH/mux и естественное истечение. Ни один из них не входит
в эти три проверки и не начинается автоматически после исправления инструкции.
