# Windows0.2.11 — исправление масштаба и разметки

Кандидат, ещё не опубликован. Публичный Windows остаётся0.2.10; Android50 и Linux0.2.10 не меняются.
Пользователь показал реальный Windows: после растягивания окна обрезаны логотип и транспорт,
маленький круг, перекрытые подписи навигации. Предыдущая native CI проверяла внешние границы,
но не обеспечивала высоты custom-painted controls в единицах DeviceDpi.

Изменения: единый отложенный первый autoscale, явные DPI-высоты header/dial/telemetry/footer,
начальное окно560×800 logical pixels, ограничение ширины содержимого720, центрирование,
повторный расчёт при смене DPI. Раскладка обоих селекторов при layout/DPI, проверки вложенных
границ и места под иконку/подпись навигации. Номер Windows0.2.11; старый установщик immutable.

Впереди: компиляция, native CI/render, проверка установщика, публикация нового файла и
повторная приёмка на ПК пользователя. Снимок пользователя с личным рабочим столом не публикуется.

Дополнительное замечание пользователя: Windows EXE/ярлык всё ещё показывал додекаэдр.
ICO16–256px и embedded brand заменены дверью из общего Android vector; генератор
старой иллюстрации больше не перезаписывает значки актуальных клиентов.

Установщик уведомляет Explorer об обновлении ассоциаций через ChangesAssociations=yes
([Inno Setup](https://jrsoftware.org/ishelp/topic_setup_changesassociations.htm)); это не гарантирует
обновление уже закреплённого пользователем ярлыка до его повторного открытия.

В startup обнаружено второе расхождение: WindowsFormsApplicationBase имеет собственный
HighDpiMode по умолчанию SystemAware, тогда как direct layout-test и проект используют
PerMonitorV2. Для обычного запуска явно выбран PerMonitorV2. Добавлена проверка через тот же
application framework без сети и сохранения настроек, с последовательным растягиванием окна.
[Исходник framework](https://github.com/dotnet/winforms/blob/main/src/Microsoft.VisualBasic.Forms/src/Microsoft/VisualBasic/ApplicationServices/WindowsFormsApplicationBase.vb).

После просмотра native PNG уточнена главная: карта остаётся во вкладке «Маршрут»,
справка о ключе — в настройках; круг адаптирует высоту150–260 logical pixels к доступной
высоте, чтобы страна и транспорт оставались ближе к кнопке подключения. На очень низком
окне доступна вертикальная прокрутка; нижняя навигация закреплена.

Пользователь запускал только ярлык после установки. Первый экран теперь явно отличает
ключ устройства от доступа: ключ создаётся локально через существующий friends-create,
для активации нужно приглашение с телефона. Нет пустой попытки серверной регистрации
для нового устройства. Добавлены кнопка активации и вставка полной ссылки как альтернатива
обработчику URI; неверная ссылка не передаётся broker. Private key не выводится.

Ярлыки установщика явно используют новый family-connect-door.ico; проверка установки
сверяет его SHA256 с исходным ICO. EXE и setup также содержат новый embedded icon.


Оформление элементов: Windows ComboBox сохраняет системную клавиатурную навигацию,
но закрытое поле, рамка, стрелка и строки списка отрисовываются в палитре приложения.
Выбранная строка выделяется фоном и бирюзовым маркером; наведение, фокус и disabled
различимы. Кнопки сохраняют собственную отрисовку и показывают нажатие пробелом;
поля приглашения больше не белые. Native UI проверяет раскрытие обоих списков
и смену страны/транспорта. Для расширенной матрицы ordinary-user CI лимит ожидания
приведён к240с, как в отдельном visual gate (раньше90с, фиксировался timeout).

При растягивании пользователь также увидел «клетки» в шапке. Custom controls теперь
используют ResizeRedraw: при изменении размера перерисовывается вся область, а не
только открывшаяся полоса с остатками старой рамки. Native regression проверяет полную
инвалидацию шапки после пяти последовательных изменений ширины. Закрашивание фона
ComboBox при WM_PRINT ограничено его ClientRectangle, чтобы не стирать соседние элементы.
