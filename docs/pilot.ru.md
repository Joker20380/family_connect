# Российский VPN: пилот для Android и Linux

[English](pilot.en.md) · [Руководство](../README.ru.md)

Текущее направление проверки: вы в Европе → controlled gateway в России → интернет.
Сервер: `185.251.89.19`, UDP-порт `51820`. Это отдельный прямой WireGuard-пилот, а не
готовое приложение Family Connect и не демонстрация адаптивного многомаршрутного VPN.

## Ключи и конфигурации

Приватные клиентские ключи создаются на вашем Linux-компьютере, не на gateway. Android и Linux
получают разные ключи и адреса, поэтому могут подключаться одновременно. На сервер передаются
только их публичные ключи. Подготовленный Android-ключ нужно перенести на телефон вместе
с конфигурацией; это ручная подготовка пилота, не будущая генерация ключа в Android Keystore.

Локальные файлы находятся в `state-v2/pilot-clients/` отдельного проекта:

- `fc-ru-android.conf` — для Android;
- `fc-ru-linux.conf` — для ноутбука Linux.

Файлы содержат приватные ключи, имеют права 0600 и исключены из Git. Передавайте Android-файл
доверенным способом, например по USB; не публикуйте его и не загружайте в онлайн-генератор QR.
На сервере этих конфигураций и приватных клиентских ключей нет.

## Android

1. Установите официальный [WireGuard](https://www.wireguard.com/install/).
2. Перенесите `fc-ru-android.conf` на телефон.
3. В WireGuard нажмите «+», импортируйте конфигурацию из файла и включите туннель.
4. Разрешите создание VPN-соединения. Проверьте внешний IPv4: ожидается `185.251.89.19`.

Для режима без обхода VPN используйте системные параметры Android «Постоянная VPN» и
«Блокировать соединения без VPN», если они доступны в вашей версии ОС. Их включение
нужно выполнить на телефоне; сервер не может включить их за вас.

## Linux

Установите инструменты WireGuard из пакетов вашего дистрибутива:
[официальные инструкции](https://www.wireguard.com/install/).

Если установлен NetworkManager, импортируйте файл через настройки сети или CLI:

```sh
sudo nmcli connection import type wireguard file /path/to/fc-ru-linux.conf
sudo nmcli connection up fc-ru-linux
```

Либо используйте `wg-quick` (поле DNS требует совместимого resolvconf):

```sh
sudo wg-quick up /path/to/fc-ru-linux.conf
sudo wg-quick down /path/to/fc-ru-linux.conf
```

Выключение NetworkManager-подключения: `sudo nmcli connection down fc-ru-linux`.
Мы не меняем маршруты или DNS вашего ноутбука автоматически при подготовке файлов.

## Поведение трафика

- Через туннель направляется весь IPv4; DNS по умолчанию — `1.1.1.1`, запросы идут через VPN.
- Маршрут IPv6 также направлен в туннель, но IPv6 egress на gateway пока заблокирован.
  Это исключает прямой IPv6-выход при активном полном туннеле; IPv6-only ресурсы не поддерживаются.
- Доступ из VPN к частным сетям gateway и TCP/25 запрещён. Произвольные публичные IPv4-соединения
  разрешены только на controlled gateway; домашние relay не участвуют в этом пилоте.
- После ручного отключения VPN обычный интернет восстанавливается. Эта конфигурация сама
  не устанавливает постоянный kill switch на ОС. Поведение Android/NetworkManager требует
  отдельной проверки на ваших устройствах, включая DNS/IPv6 и смену Wi-Fi/LTE.
- Российский IP не гарантирует доступ к любому российскому сервису: отдельные сайты используют
  собственную геобазу, блокируют адреса дата-центров или имеют дополнительные требования.
- Прямой WireGuard может быть недоступен в некоторых сетях. Автоматического fallback на relay
  в этих конфигурациях ещё нет.

## Оператору

Отдельный Compose-проект `family-connect-pilot` использует `compose.pilot.yaml`.
Он не заменяет mTLS-стенд и его каталог. Отзыв через `scripts/admin.py` относится к mTLS;
для WireGuard нужно удалить соответствующий peer и его конфигурацию на gateway отдельно.

```sh
docker compose -f compose.pilot.yaml up -d --build
docker compose -f compose.pilot.yaml exec gateway wg show wg0
```

Серверный ключ хранится в `state-v2/wireguard/server.key`, публичные клиентские — в
`android.pub` и `linux.pub`. Подготовку клиентских ключей выполняет локальный
`scripts/create_pilot_clients.py`; не запускайте его на gateway для реальных пользователей.
NAT и фильтрация находятся внутри gateway-контейнера. Это ограниченный пилот на два устройства,
без billing, автоматической ротации, динамической регистрации или полноценной anti-abuse системы.
