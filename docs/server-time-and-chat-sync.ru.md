# Время серверов и синхронизация участников чата

RU выдаёт membership snapshot на100 секунд; NL принимает только expires_at в
интервале (now, now+120]. После истечения срока динамические участники теряют доступ
до следующего корректного обновления. Списки и ключи не выводить в журналы.

При вводе нового сервера, переносе из backup и инциденте chat-sync проверить:

1. `timedatectl show -p NTPSynchronized`: должно быть yes на обоих узлах.
2. Для chrony: `chronyc tracking`, `chronyc sources -n`, `chronyc authdata`.
   Требуются выбранный источник, Leap status Normal и свежие измерения; active
   у службы само по себе не означает синхронизацию. Для NTS проверять успешную
   аутентификацию/полученные cookies. Рабочая цель — расхождение менее1 секунды;
  20 секунд — уже весь запас текущего membership протокола.
3. RU timer active; последняя oneshot service Result=success/ExecMainStatus=0.
   ActiveState=inactive после успешной oneshot — нормальное состояние.
4. На NL список не просрочен, sequence увеличивается после следующих запусков,
   набор участников совпадает с authoritative desired_members RU. Сравнивать
   внутри закрытого процесса; наружу только boolean и агрегированные количества.
5. Проверить mailbox/AWG/TCP и отдельно пользовательскую отправку/получение.

На NL установлен дополнительный источник из
[deploy/time/family-connect.sources](../deploy/time/family-connect.sources).
Целевой путь `/etc/chrony/sources.d/family-connect.sources`, root:root0644;
основной chrony.conf должен подключать этот sourcedir. Источники дистрибутива
сохранены. После установки: `chronyc reload sources`, `chronyc refresh`,
`chronyc burst 4/4`, затем проверить фактический результат. Перезапуск VPN не нужен.
NTS требует доступности TCP4460 и NTP-трафика; доступный TCP сам по себе не доказывает
получение измерений. При восстановлении синхронизации возможна коррекция wall clock
согласно действующей политике chrony (на NL makestep1/3); учитывать короткие leases.
Не отключать TLS-проверки NTS и не увеличивать TTL ради обхода неисправных часов.

Откат: убрать только добавленный файл sources, выполнить reload sources и проверить
оставшиеся источники. Если они по-прежнему недоступны, откат вернёт отсутствие
надёжной синхронизации. Часы назад вручную не переводить.

Настройка дополнительного источника выполнена только на NL; RU уже synchronized.
Это не система оповещений: автоматический alert на clock drift/expired membership
ещё требуется включить в мониторинг парка. Один рабочий NTS-провайдер остаётся
зависимостью; следующий резервный источник нужно принимать измерениями, не только DNS.

Команды reload/burst описаны в [официальной документации chrony](https://chrony-project.org/doc/4.6/chronyc.html).
