# Реестр потребителей секретов: публичная схема

Фактический инвентарь с путями, хешами, режимами, состоянием копии и назначением
сохранён только внутри KeePassXC. Здесь перечислены категории и границы миграции.
204 файла реестра — не204 отдельных производственных секрета: туда входят
сопутствующие настройки, публичные материалы и локальное pilot state.

| Категория | Потребители | Состояние / следующий результат |
| --- | --- | --- |
| Корневой ключ подписи | Пять issuers через scripts/signing_key.py | Vault loader реализован; проверка настоящего ключа по anchor выполнена; файловые оригиналы сохранены |
| Android keystore и данные доступа | Инструменты подписи APK | Vault entry point реализован и проверен на synthetic APK; production signing acceptance впереди |
| Операторские activation identities | Локальные activation helpers | Копия сверена; проверить фактически используемые команды перед миграцией |
| Локальное enrollment/VPN state | Клиенты и пилотные инструменты | Разделить действующие и исторические экземпляры; три SQLite требуют проверки актуальности |
| Административное восстановление FC | Оператор доступа к серверу | Дополнительный credential сохранён и извлечён побайтно; исходник пока оставлен |
| Серверные рабочие credentials/state | Friends API, AWG/TCP, TLS, SSH, mailbox | Отдельные зашифрованные server snapshots; проверен ограниченный restore rehearsal; рабочие файлы необходимы службам |

Для закрытой записи обязательны: назначение/владелец, подтверждённый потребитель,
рабочий путь и режим доступа, backup entry/date, способ восстановления,
порядок отзыва/ротации и критерий устранения оригинала. Текущая запись — начальный
реестр категорий/путей; полный список внешних shell helpers и процедуры ротации для
каждого файла ещё не подтверждены. Не считать этот этап завершением всей миграции.

backup payload hashes;3 SQLite классифицированы отдельно, поскольку online backup
не обязан совпадать побайтно с live database. Изменившихся обычных файлов не найдено.
В vault добавлен ещё1 административный credential; инвентарь и credential находятся
в encrypted attachment с проверенным binary export/SHA256. Старая encrypted KDBX
сохранена локально, внешний носитель ещё не подключён.

У7 локальных файлов права изменены на0600. Их родитель уже имел0700, поэтому
прежние file modes сами по себе не доказывают доступ постороннего пользователя.
В закрытом инвентаре записан режим на момент сканирования, до этого сужения прав.
Исходники не удалялись. Архивы в plaintext на диск не записывались.

Далее: принять Android vault signing при следующем выпуске, проверить актуальность выбранных SQLite
и active/legacy identities, довести процедуры ротации, затем независимая внешняя копия.
Удаление рабочих оригиналов — отдельное действие после проверки каждого потребителя;
не подменять миграцию массовым удалением каталогов.
