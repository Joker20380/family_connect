# Bounded browser admission candidate — local only

This is a product change to the retained speed/recovery pair, not a diagnostic-only
change, a claim of repaired owner browsing, or authorization to deploy.
The preceding [local reproduction](../browser-admission-20261017/README.md) remains
unchanged. No baseline/root-main reconstruction, credentials or live provider is used.

## Changes and bounds

- Ordinary mux streams:32→64. Opt-in client FIFO admission holds at most32 callers;
  pending callers have no mux stream/window allocated. Queue time consumes the existing
 40-second open budget, not an additional timeout. Overflow/cancel/timeout are counted.
- One reserved lease stream uses the existing exact control destination and configured
  server callback. Data saturation cannot consume its slot. The existing authenticated
  renewal protocol, sequence/replay/floor/revocation checks and security limit remain.
  One additional pending lease is allowed only while the prior reserved stream is
  terminal and awaiting removal; another live lease is rejected. Total pending≤33.
- Wholedevice allows96 ordinary handlers (active+waiting),16 DNS handlers and4 service
  handlers. TCP DNS now uses the DNS pool like UDP DNS. The real mux, shared with chat,
  still caps ordinary streams at64, not96. No valid idle/long-lived flow is evicted.
- The existing pinned Xray/gVisor integration completes a SYN forwarder request after
  endpoint creation, not after the entire established TCP connection closes. Its64
  in-flight handshake cap is unchanged. This avoids consuming SYN slots with established
  sockets; it does not remove endpoint or wholedevice/mux resource bounds.
- The existing native→Java→ring→normal bundle pipeline retains packet `limit_denied`
  and six mux admission counters. No new native-stats reader or destination/identity
  field is introduced. Missing old fields remain missing; first failure stays immutable.

ReliableStream/media/async-writer/queue64, UI60-4, JNI contract, security durations,
broker ownership, retry/recovery and the120-second startup budget are unchanged.
The previously installed early-retransmit change is retained, not independently fixed
or newly accepted here. This is a bounded capacity/admission fix, not a throughput
benchmark:64 indefinitely held data flows can still exhaust the unchanged open deadline.
Older peers still enforce their lower cap; do not claim mixed-pair capacity acceptance.

## Reproduction and safety

Scripts are archived execution receipts and expect the private retained directory
layout `state-client-build/browser-admission-fix-1` relative to their location. Copy
them there for execution, preserve the recorded parents, and choose fresh output
directories. They are not a source downloader or a production runbook.

`check.py` records the original batch; `check_followup.py` records the fixture correction
and enabled real lease tests. Fixed normal/race counts, fail-fast, no retry-until-pass.
Both reuse the retained thermal runner in `reliable-full-stack-1/run.py` and offline
toolchain/cache; follow-up refuses skipped lease results. Run under a user systemd
scope with `CPUQuota=50%`, `MemoryMax=3G`, `TasksMax=160`, no emulator. Start below75°C;
terminate at85°C. `seal.py` checks exact allowed changes and preserved parent files.
`bounded.py` runs `build.py` once with a30-minute ceiling; `check_artifact.py` verifies
the resulting unsigned APK, embedded native/provenance, package/ABI/API and alignment.

Raw disposable credentials, build artifacts and phone export remain private. Published
logs contain synthetic local traffic only. No signing, phone/server access, CONNECT,
installation, service operation or public release is performed by this local work.
