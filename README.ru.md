# Family Connect — русский

[English](README.en.md) · [Оглавление документации](README.md)

Стабильная защищённая связь для семьи независимо от границ. Покупатель — член семьи
в Европе; первые целевые пользователи — родственники в России. Будущий продукт предлагает
семейную подписку, приглашения и одну кнопку подключения с автоматическим выбором маршрута.

## Практический пилот: Европа → Россия

Для Android и Linux подготовлен отдельный прямой WireGuard-пилот на российском сервере
`185.251.89.19`. У устройств разные ключи. Это реальный IPv4-выход в интернет, но пока
без интеграции с Rust discovery, семейными аккаунтами и автоматическим выбором relay.
[Подключение и ограничения](docs/pilot.ru.md).

## Текущий этап: стенд аутентификации и обнаружения узлов

- Взаимная аутентификация TLS 1.3 во внешних QUIC-соединениях клиент—relay и в отдельном
  внутреннем QUIC-соединении клиент—gateway. Общий токен в открытом виде удалён.
- Сертификаты устройств от оператора и явное членство в подписанном состоянии сети.
  Одного сертификата CA недостаточно: устройство должно быть разрешено в каталоге.
  Relay и gateway имеют отдельные серверные ключи; клиент дополнительно сверяет сертификаты
  с отпечатками из подписанного каталога.
- Rust проверяет подпись Ed25519, закреплённый корень доверия, срок действия, схему, роли,
  уникальность identity и сохранённые на диске максимальные epoch/время выпуска.
- Адреса берутся из проверенного каталога. Порядок bootstrap URL настраивается.
  Действительный подписанный кэш позволяет запускаться и работать без backend.
- Локальные команды оператора revoke/enroll увеличивают epoch. Узлы обновляют каталог
  раз в пять секунд и проверяют активные соединения раз в секунду. Приватные ключи устройств
  не отправляются control API. Регистрация пока выполняется оператором, публичного onboarding API нет.
- Внутренний QUIC сохраняется при переключении между аутентифицированными relay.
  Relay использует заданное оператором имя gateway, а не IP/порт из клиентского пакета.
- Изолированная Docker-сеть без публичных портов data plane и выхода в интернет.
  API доступен только через localhost хоста. Ключи устройств, узлов и подписи состояния
  подключаются в разные контейнеры раздельно.

## Быстрый запуск

Нужны Linux, Docker Compose и Python 3. Подготовка ключей выполняется администратором.

```sh
docker compose build
sudo ./scripts/provision.sh
docker compose up -d control gateway relay-a relay-b
./scripts/test_failover.sh
./scripts/test_auth.sh
./scripts/test_offline.sh
python3 scripts/test_revocation.py
```

В [эксплуатации](docs/operations.ru.md) описаны перезапуск, защита ключей и просмотр API;
в [проверках](docs/testing.ru.md) — что именно доказывает каждый тест.

## Границы результата

Это всё ещё Phase 0, а не Android VPN, публичная добровольческая сеть или доказательство
устойчивости к блокировкам. Передаются сгенерированные тестовые данные, а не IP-пакеты из TUN.
Смена gateway, мобильные переходы, независимые транспорты и публичная регистрация ещё впереди.

В стенде используются один CA и онлайн-ключ Ed25519 для состояния сети. Для production
ещё нужны жизненный цикл offline root/intermediate, безопасная регистрация, ротация
сертификатов, аппаратное хранение ключей, более строгие лимиты на устройство и независимый аудит.

Кэш разрешает работу только до подписанного срока действия, обычно 15 минут.
При полной недоступности backend отзыв нельзя доставить мгновенно. После истечения срока
прототип закрывает сессии, а не продлевает доступ бессрочно. Отсутствие свежего состояния
не означает неограниченную автономную работу.

Для стенда QUIC внутри QUIC внешний UDP MTU зафиксирован на 1400, внутренний — на 1200.
Это подходит для данной Docker-проверки, но ещё не проверено на произвольных мобильных путях.
Детектор смены маршрута ориентируется на ответы при активной загрузке; это не полноценная
проверка доступности простаивающих соединений.
